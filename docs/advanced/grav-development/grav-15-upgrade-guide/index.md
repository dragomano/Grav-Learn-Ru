# Обновление с Grav <1.6 {: #upgrading-from-grav-1-6 }

> [!NOTE] Примечание
> Это руководство проверено на Grav v1.2.0 и всех последующих версиях.

> [!CAUTION] Внимание
> **ВНИМАНИЕ**: обновление Grav сразу до последней версии работает, но полностью не поддерживается и, скорее всего, сломает ваш сайт!

## Подготовка

Самый простой способ обновить старые версии Grav — создать копию сайта на сервере Linux/Unix с установленным **PHP 7.3** и поддержкой входа по SSH для доступа к командам CLI. Это руководство также работает с подсистемой Linux для Windows 10, но если она у вас не установлена, пакеты обновления, возможно, придётся скачивать и переименовывать вручную.

**PHP 7.3** выбран потому, что это единственная версия PHP, которую можно использовать для всех версий Grav. Можно также использовать PHP 7.1 или 7.2, но тогда Grav можно обновить только до v1.6.31. В этот момент перед продолжением обновления нужно будет переключиться на PHP 7.3 или 7.4. PHP 8 следует использовать только после обновления до Grav 1.7 или более поздней версии.

Это руководство включает инструкции по обновлению **Grav** и наиболее часто используемых пакетов: **Problems**, **Error**, **Form**, **Email**, **Login** и **Admin**. Для всех остальных плагинов убедитесь, что они всё ещё поддерживаются и поддерживают и Grav 1.6, и последнюю версию Grav. На момент написания этого руководства почти все активно поддерживаемые плагины должны попадать в эту категорию. Самые безопасные плагины — те, что были обновлены после выпуска Grav 1.7.0 (18.01.2021) или подтверждённо работают в Grav 1.7.

Вашей **теме** и любым **пользовательским** или **неподдерживаемым плагинам** потребуется больше работы. Любой пользовательский код следует проверить, чтобы убедиться, что он всё ещё работает с текущими версиями Grav и PHP. То же верно для файлов **Markdown**, **YAML** и **twig**: в последних версиях библиотек есть исправления, которые ловят ошибки, а значит, разбор сломанных файлов обычно будет завершаться ошибкой. Более новые версии Grav дают инструменты для проверки этих файлов, но проверки ловят не все проблемы, поэтому тестирование тоже нужно.

Контрольный список (с использованием консоли и Grav CLI):

* Сделайте резервную копию
* Определите версию Grav командой `bin/gpm version grav`
* Проверьте версию PHP CLI командой `php -v`, это должна быть **PHP 7.3** (>=7.3.6)
* Проверьте версию PHP на сервере, она должна совпадать с версией в CLI
* Перечислите все установленные плагины и разложите их по категориям (поддерживаемые, пользовательские, неподдерживаемые)
* Сделайте то же самое с темой

## Шаг до Grav 1.6.31 {: #step-to-grav-1-6-31 }

Эта часть предполагает, что вы уже сделали копию сайта и команды CLI работают. Пользователям Windows без установленной подсистемы Linux нужно скачать файлы вручную и переименовать их.

Выполните следующие команды в корневой папке сайта Grav (опустите параметр `-y` в команде GPM, если вы используете Grav 1.2 или ниже):

```bash
wget -q https://getgrav.org/download/core/grav-update/1.6.31 -O tmp/grav-update-v1.6.31.zip

bin/gpm direct-install -y tmp/grav-update-v1.6.31.zip
```

Grav можно обновить и вручную. Удалите следующие папки: `assets bin system vendor  webserver-configs` и скопируйте/перезапишите **все** файлы из zip-архива обновления Grav, [найденного здесь](https://getgrav.org/download/core/grav-update/1.6.31). Учтите, что файлы в архиве находятся внутри папки `grav-update`.

Далее нужно обновить базовые плагины.

```bash
wget -q https://getgrav.org/download/plugins/problems/2.0.3 -O tmp/grav-plugin-problems-v2.0.3.zip
wget -q https://getgrav.org/download/plugins/error/1.7.1 -O tmp/grav-plugin-error-v1.7.1.zip
wget -q https://getgrav.org/download/plugins/form/4.3.0 -O tmp/grav-plugin-form-v4.3.0.zip
wget -q https://getgrav.org/download/plugins/email/3.1.0 -O tmp/grav-plugin-email-v3.1.0.zip
wget -q https://getgrav.org/download/plugins/login/3.3.8 -O tmp/grav-plugin-login-v3.3.8.zip
wget -q https://getgrav.org/download/plugins/admin/1.9.19 -O tmp/grav-plugin-admin-v1.9.19.zip


bin/gpm direct-install -y tmp/grav-plugin-problems-v2.0.3.zip
bin/gpm direct-install -y tmp/grav-plugin-error-v1.7.1.zip
bin/gpm direct-install -y tmp/grav-plugin-form-v4.3.0.zip
bin/gpm direct-install -y tmp/grav-plugin-email-v3.1.0.zip
bin/gpm direct-install -y tmp/grav-plugin-login-v3.3.8.zip
bin/gpm direct-install -y tmp/grav-plugin-admin-v1.9.19.zip
```

Либо плагины можно установить вручную: просто удалите все файлы в `user/plugins/pluginnname` и скопируйте файлы обратно из zip-архива. Учтите, что файлы в архиве находятся внутри папки со случайным именем.

## Обновление до Grav 1.7 {: #upgrading-to-grav-1-7 }

Запустите следующие команды CLI по одной и следуйте их инструкциям:

```bash
bin/gpm self-upgrade
bin/gpm update
```

Возможно, вы также захотите обновить другие плагины по одному до последней версии, но делайте это только если последняя версия плагина поддерживает Grav 1.6. Остальные плагины следует отключить, если вы не уверены, что они будут работать. Их можно снова включить позже, когда будете тестировать сайт.

> [!NOTE] Примечание
> Если у вас нет сломанных плагинов, панель администрирования и сайт на этом этапе должны полностью работать.

> [!CAUTION] Внимание
> **ВНИМАНИЕ**: не обновляйте Grav или плагин Admin дальше, пока не прочитали **[Обновление до Grav 1.7](../grav-17-upgrade-guide/index.md)**. Иначе можно сломать и сайт, и панель администрирования.
