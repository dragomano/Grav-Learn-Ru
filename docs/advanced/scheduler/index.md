# Планировщик

Планировщик Grav — новая фича, появившаяся в Grav 1.6 и позволяющая запускать задания периодически. В основе обработки лежит **cron**-планировщик сервера, но после добавления одной записи в службу cron все задания и конкретные расписания можно настраивать через Grav.

Одно из главных преимуществ использования планировщика для задач — их можно выполнять без участия пользователя и независимо от фронтенда. Такие задачи, как периодическая очистка кэша, резервное копирование, синхронизация, индексация поиска и т. п., — все они отлично подходят для заданий по расписанию.

## Установка

Первый шаг к настройке планировщика и подготовке его к работе — добавить команду `bin/grav scheduler` в службу cron. Проще всего воспользоваться самой командой CLI, чтобы она вывела подходящую команду для установки:

```bash
$ bin/grav scheduler -i

Install Scheduler
=================

 [ERROR] You still need to set up Grav's Scheduler in your crontab

 ! [NOTE] To install, run the following command from your terminal:

 (crontab -l; echo "* * * * * cd /Users/andym/grav;/usr/local/bin/php bin/grav scheduler 1>> /dev/null 2>&1") | crontab -
```

В моей системе на mac выводится полная требуемая команда, так что достаточно скопировать её целиком в терминал и нажать Enter.

> [!CAUTION] Внимание
> Нужно войти в оболочку под тем же пользователем, что и ваш веб-сервер. Это гарантирует, что пользователь, запускающий команды планировщика, совпадает с пользователем веб-сервера, которому нужно взаимодействовать с этими файлами. Если установить запись crontab под другим пользователем (например, `root`), все создаваемые файлы будут создаваться от этого пользователя `root`, а не от пользователя `webserver`, что может привести к проблемам.

```bash
(crontab -l; echo "* * * * * cd /Users/andym/grav;/usr/local/bin/php bin/grav scheduler 1>> /dev/null 2>&1") | crontab -
```

 Ответа не будет, но и ошибок быть не должно. После этого можно убедиться, что всё в порядке, повторно запустив команду `bin/grav scheduler -i`:

```bash
bin/grav scheduler -i

Install Scheduler
=================

 [OK] All Ready! You have already set up Grav's Scheduler in your crontab
```

Нужную команду также можно получить в плагине админки, просто перейдя в **Tools** → **Scheduler**.

> [!WARNING] Предупреждение
> **Переопределения окружения:** когда `bin/grav scheduler` запускается из cron без явного указания окружения, Grav определяет окружение как `cli`, а не по имени хоста вашего сайта. Поэтому всё, что задано только в переопределении окружения, например в `user/env/www.example.com/config/scheduler.yaml` (пользовательские задания, а также настройки плагинов или резервного копирования для конкретного окружения), этим запуском никогда не загружается, хотя админка, работающая под именем хоста, показывает такие задания как готовые. Если ваш сайт использует `user/env/<host>/`, добавьте `--env=<host>` в строку планировщика в crontab (начиная с Grav 2.0.20 команда, показываемая в админке и командой `bin/grav scheduler --env=<host> -i`, включает его) или экспортируйте `GRAV_ENVIRONMENT=<host>` в crontab, что дополнительно загрузит файл `.env.<host>`. Задание, определённое в базовом `user/config/scheduler.yaml`, выполняется в любом окружении.

## Основы расписания

Чтобы запланировать задание, частота задаётся гибким форматом.

```text
* * * * * *
| | | | | |
| | | | | +-- Year              (range: 1900-3000)
| | | | +---- Day of the Week   (range: 1-7, 1 standing for Monday)
| | | +------ Month of the Year (range: 1-12)
| | +-------- Day of the Month  (range: 1-31)
| +---------- Hour              (range: 0-23)
+------------ Minute            (range: 0-59)
```

Несколько примеров:

`0 * * * *`	запуск раз в час (каждый час в нулевую минуту)
`0 0 * * *`	запуск раз в день (каждый день в полночь, в нулевую минуту)
`0 0 1 * *`	запуск раз в месяц (в первый день каждого месяца в полночь, в нулевую минуту)
`0 0 1 1 *`	запуск раз в год (в первый день первого месяца каждого года в полночь, в нулевую минуту)

Дополнительные возможности:

`*/5 * * * *` запуск каждые 5 минут

```bash
 ! [NOTE] For error details run "bin/grav scheduler -d"
```

Планировщик Grav управляется основным файлом конфигурации. Он находится в `user/config/scheduler.yaml`, и для запуска любое задание должно быть в нём `enabled`.

Ниже в конфигурации показаны доступные задания и то, включены ли они для запуска. Просто установите запись в `disabled`, чтобы остановить её выполнение.

```yaml linenums="1"
status:
  ls-job: enabled
  cache-purge: enabled
  cache-clear: enabled
  default-site-backup: enabled
  pages-backup: enabled
```

Чтобы увидеть больше подробностей о возможных **ошибках** или узнать время следующего запуска задания, используйте команду `/bin/grav scheduler -d`:

## Ручной запуск заданий

Команда CLI даёт простой способ вручную запустить любое задание. Собственно, именно это планировщик и делает при периодическом запуске.

```bash
bin/grav scheduler
```

Она молча выполнит задания, но подробности того, что запускалось, можно увидеть так:

```bash
bin/grav scheduler -v
```

## Системные задания Grav

Ядро Grav из коробки предоставляет несколько заданий. Среди них есть полезные задачи обслуживания:

* `cache-purge` — эта задача полезна, если вы используете `file`-кэширование Grav, так как она удаляет старые файлы с истёкшим сроком. Это отличная задача для расписания, иначе пользователю пришлось бы вручную очищать старый кэш. Если за этим не следить, а место на диске ограничено, можно исчерпать место и уронить сервер.

* `cache-clear` — очистка кэша; эта задача работает так же, как команда `bin/grav clear`, которую вы запускали бы вручную. Можно настроить `standard`-очистку кэша или вариант `all`, который удаляет все файлы и папки в папке `cache/` для более полной очистки.

* `default-site-backup` — задание резервного копирования по умолчанию, доступное через новую конфигурацию резервных копий Grav. Можно создавать собственные конфигурации резервного копирования, и они также будут доступны для запуска как задание по расписанию.

## Пользовательские задания

Планировщик Grav можно вручную настроить с любым числом пользовательских заданий. Их можно задать в том же файле конфигурации `scheduler.yaml`, о котором говорилось выше. Например, упомянутое выше задание `ls-job` настраивалось бы так:

```yaml linenums="1"
custom_jobs:
  ls-job:
    command: ls
    args: '-lah'
    at: '* * * * *'
    output: logs/cron-ls.out
    output_mode: overwrite
    email: user@email.com
```

Команда должна быть любым локальным скриптом, который можно запустить из командной строки/терминала. Обязательны только атрибуты `command` и `at`.

## Задания от плагинов

Одна из самых мощных фич планировщика Grav — способность сторонних плагинов предоставлять собственные задания. Отличный пример даёт плагин `TNTSearch`. TNTSearch — полнофункциональный поисковый движок по тексту, которому перед поиском нужно проиндексировать контент. Эту индексацию можно выполнять разными способами, но планировщик Grav позволяет периодически переиндексировать контент, а не делать это вручную.

Первый шаг — ваш плагин должен подписаться на событие `onSchedulerInitialized()`. Затем создайте в файле плагина метод, который при вызове добавляет пользовательское задание:

```php linenums="1"
public function onSchedulerInitialized(Event $e): void
{
    $config = $this->config();

    if (!empty($config['scheduled_index']['enabled'])) {
        $scheduler = $e['scheduler'];
        $at = $config['scheduled_index']['at'] ?? '* * * * *';
        $logs = $config['scheduled_index']['logs'] ?? '';
        $job = $scheduler->addFunction('Grav\Plugin\TNTSearchPlugin::indexJob', [], 'tntsearch-index');
        $job->at($at);
        $job->output($logs);
        $job->backlink('/plugins/tntsearch');
    }
}
```

Здесь видно, как из настроек конфигурации плагина TNTSearch берётся часть конфигурации планировщика, а затем создаётся новое `Job` со **статической** функцией `indexJob()`.
