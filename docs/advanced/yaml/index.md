# Синтаксис YAML

Введение
-----

YAML расшифровывается как _"YAML Ain't Markup Language"_ и широко используется в Grav для файлов конфигурации, схем, а также настроек страниц.

YAML для конфигурации — то же, что Markdown для разметки. По сути, это удобный для человека формат структурированных данных. Он проще и легче XML или JSON, но даёт похожие возможности. По сути, он позволяет задавать мощные настройки конфигурации, не изучая более сложные языки вроде CSS, JavaScript и PHP.

YAML изначально создавался простым в использовании. В своей основе YAML-файл описывает данные. Одно из преимуществ YAML в том, что информацию из одного YAML-файла легко перевести в несколько языковых типов.

По сути, данные, которые вы вносите в YAML-файл, используются вместе с библиотекой для создания страниц, которые вы видите в Grav.

Основные правила YAML
-----

В YAML есть ряд правил, позволяющих избежать проблем, связанных с неоднозначностью в разных языках и редакторах. Благодаря этим правилам один YAML-файл интерпретируется одинаково независимо от того, какое приложение и/или библиотека его обрабатывает.

* В Grav YAML-файлы по возможности должны иметь расширение `.yaml`.
* YAML чувствителен к регистру.
* YAML не допускает использования табуляции.

Основные типы данных
-----

YAML лучше всего работает с **отображениями** (хешами / словарями), **последовательностями** (массивами / списками) и **скалярами** (строками / числами). Хотя его можно использовать с большинством языков программирования, лучше всего он подходит языкам, построенным вокруг этих типов структур данных. Среди них: PHP, Python, Perl, JavaScript и Ruby.

## Скаляры

Скаляры — довольно простое понятие. Это строки и числа, из которых состоят данные на странице. Скаляром может быть логическое свойство, например `true`, целое число (number), например `5`, или строка текста, например предложение или заголовок вашего сайта.

В программировании скаляры часто называют переменными. Если бы вы составляли список видов животных, скалярами были бы названия этих животных.

Большинство скаляров не заключается в кавычки, но если вы вводите строку с пунктуацией и другими элементами, которые можно спутать с синтаксисом YAML (тире, двоеточия и т. д.), такую строку лучше заключить в одинарные `'` или двойные `"` кавычки. Двойные кавычки позволяют использовать escape-последовательности для представления символов ASCII и Unicode.

```yaml linenums="1"
integer: 25
string: "25"
float: 25.0
boolean: true
```

> [!WARNING] Предупреждение
> **Совет:** Слова `true`, `false`, `null`, `~` и даты имеют в YAML особое значение. Заключайте их в кавычки, если не хотите использовать их как логическое значение, null или тип даты-времени. То же верно для номеров версий: их следует заключать в кавычки, чтобы отделить от значений с плавающей точкой.

## Последовательности

Вот простая последовательность, которую можно встретить в Grav. Это базовый список, где каждый элемент расположен на отдельной строке с тире в начале.

```yaml linenums="1"
- Cat
- Dog
- Goldfish
```

В этой последовательности каждый элемент списка находится на одном уровне. Если нужно создать вложенную последовательность с элементами и подэлементами, добавьте по одному пробелу перед тире в подэлементах. YAML использует для отступов пробелы, **А НЕ** табуляцию. Пример приведён ниже.

```yaml linenums="1"
-
 - Cat
 - Dog
 - Goldfish
-
 - Python
 - Lion
 - Tiger
```

Если хотите вложить последовательности ещё глубже, просто добавьте больше уровней.

```yaml linenums="1"
-
 -
  - Cat
  - Dog
  - Goldfish
```

Последовательности можно добавлять и в другие типы структур данных, например в отображения или скаляры.

## Отображения

Отображение позволяет перечислять ключи со значениями. Это полезно, когда вы назначаете имя или свойство конкретному элементу.

```yaml linenums="1"
animal: pets
```

Этот пример сопоставляет значение `pets` ключу `animal`. В сочетании с последовательностью вы увидите, что начинаете строить список `pets`. В следующем примере тире, помечающее каждый элемент, считается отступом, поэтому элементы списка становятся дочерними, а строка отображения `pets` — родительской.

```yaml linenums="1"
pets:
 - Cat
 - Dog
 - Goldfish
```
