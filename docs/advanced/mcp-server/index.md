# Сервер Grav MCP

[Сервер Grav MCP](https://github.com/getgrav/grav-mcp) открывает сайт Grav 2.0 агентным ИИ-клиентам через [Model Context Protocol](https://modelcontextprotocol.io) (MCP). Это отдельное приложение на **Node.js**, распространяемое как пакет [`grav-mcp`](https://www.npmjs.com/package/grav-mcp) в npm. Это **не** плагин Grav: он работает внутри вашего ИИ-клиента (Claude Code, Claude Desktop, Cursor или любого клиента, поддерживающего MCP) и общается с вашим сайтом по HTTP через официальный [плагин API Grav](../../api/index.md).

Принцип устройства прост: **Admin2 — клиент для людей, сервер MCP — клиент для ИИ, и оба идут через один и тот же API**. У сервера MCP нет привилегированного чёрного хода в Grav. Каждая выполняемая им операция — это аутентифицированный HTTP-запрос с проверкой разрешений к `/api/v1`, точно как у любого другого потребителя API.

> [!WARNING] Предупреждение
> Для сервера MCP нужен установленный и включённый на целевом сайте Grav [плагин API](../../api/index.md). Сам сервер MCP не содержит логики работы с контентом; это слой трансляции между вызовами инструментов MCP и REST API Grav.

## Архитектура

```
┌─────────────────┐   stdio / HTTP    ┌──────────────┐   HTTPS + X-API-Key   ┌──────────────────┐
│   AI Client     │ ◀──────────────▶  │  grav-mcp    │ ◀───────────────────▶ │  Grav API Plugin │
│ (Claude, etc.)  │   MCP protocol    │ (Node.js)    │   REST /api/v1        │  (PHP, on site)  │
└─────────────────┘                   └──────────────┘                       └──────────────────┘
```

1. ИИ-клиент запускает `grav-mcp` как подпроцесс (транспорт stdio) или подключается к работающему экземпляру (транспорт HTTP).
2. `grav-mcp` объявляет клиенту свой каталог **инструментов**, **ресурсов** и **подсказок**.
3. Когда модель вызывает инструмент, `grav-mcp` превращает вызов в аутентифицированный HTTP-запрос к API Grav.
4. Плагин API аутентифицирует запрос, проверяет разрешения, выполняет операцию с файловой системой и возвращает структурированный JSON.

Поскольку плагин API — единственная точка изменения, сервер MCP бесплатно наследует модель разрешений API, оптимистичный контроль параллелизма (ETag), ограничение частоты запросов и систему событий/вебхуков.

## Требования

- **Node.js 18+** на машине, где запущен ИИ-клиент.
- Сайт Grav 2.0 с установленным и включённым **плагином API**.
- Ключ API, созданный для пользователя, от имени которого должен действовать ИИ.

## Установка и настройка

Вручную устанавливать ничего не нужно. Пакет `grav-mcp` запускается по требованию через `npx`, поэтому вся настройка происходит в вашем ИИ-клиенте.

### 1. Создайте ключ API

На сайте Grav создайте ключ для подходящего пользователя (перед выбором пользователя см. [Разрешения и безопасность](#permissions-and-security)):

```bash
bin/plugin api keys:generate --user=admin --name="Claude MCP"
```

Ключ (с префиксом `grav_`) показывается один раз. Скопируйте его сразу. Команды управления ключами (`keys:list`, `keys:revoke`) описаны в справочнике [Аутентификация API](../../api/authentication/index.md).

### 2. Зарегистрируйте сервер в ИИ-клиенте

Сервер MCP настраивается через две переменные окружения: `GRAV_API_URL` (базовый URL API вашего сайта) и `GRAV_API_KEY` (только что созданный ключ).

**Claude Code / Claude Desktop / Cursor** и большинство клиентов MCP используют стандартный блок конфигурации `mcpServers`:

```json
{
  "mcpServers": {
    "grav": {
      "command": "npx",
      "args": ["-y", "grav-mcp"],
      "env": {
        "GRAV_API_URL": "https://my-site.example/api",
        "GRAV_API_KEY": "grav_your_api_key_here"
      }
    }
  }
}
```

Перезапустите (или переподключите) клиент — и полный набор инструментов Grav станет доступен.

### 3. (Необязательно) Запуск напрямую для тестирования

Та же конфигурация работает в командной строке:

```bash
GRAV_API_URL=https://my-site.example/api GRAV_API_KEY=grav_abc123 npx grav-mcp
```

## Справочник конфигурации

Каждый параметр можно задать переменной окружения или флагом CLI. Флаги CLI имеют приоритет.

| Переменная окружения | Флаг CLI | Обязательный | Описание |
|----------------------|----------|----------|-------------|
| `GRAV_API_URL`       | `--url`         | Да | Базовый URL API Grav (например, `https://my-site.example/api`). |
| `GRAV_API_KEY`       | `--key`         | Да | Ключ API для аутентификации. Должен начинаться с `grav_`. |
| `GRAV_ENVIRONMENT`   | `--environment` | Нет  | Нацеливает на конкретное окружение `user/env/*` для областей конфигурации (передаётся заголовком `X-Config-Environment`). |
| —                    | `--transport`   | Нет  | `stdio` (по умолчанию) или `http`. |
| —                    | `--port`        | Нет  | Порт для транспорта HTTP. По умолчанию `3100`. |

## Транспорты

### stdio (по умолчанию)

Транспорт по умолчанию. ИИ-клиент запускает `grav-mcp` как дочерний процесс и общается через стандартный ввод/вывод. Это правильный выбор для локальных однопользовательских клиентов, таких как Claude Code, Claude Desktop и Cursor.

### HTTP

Для удалённых или многопользовательских развёртываний запустите долгоживущий сервер, к которому клиенты подключаются по HTTP:

```bash
npx grav-mcp --url https://my-site.example/api --key grav_abc123 --transport http --port 3100
```

## Аутентификация

Каждый запрос сервера MCP несёт ключ API в заголовке `X-API-Key`:

```
X-API-Key: grav_abc123...
```

Это та же аутентификация по ключу API, что описана в справочнике [Аутентификация API](../../api/authentication/index.md). Когда задан `GRAV_ENVIRONMENT`, сервер также отправляет заголовок `X-Config-Environment`, чтобы чтение и запись конфигурации нацеливались на правильное окружение.

При запуске клиент проверяет свой ключ через эндпоинт API `/me`, чтобы прочитать действующие разрешения пользователя: так о неподдерживаемых операциях можно сообщить сразу, а не когда они сорвутся позже.

## Разрешения и безопасность {: #permissions-and-security }

Самое важное, что нужно понять о модели безопасности сервера MCP: **он наследует разрешения пользователя, которому принадлежит его ключ API, и ничего больше**. Отдельного набора разрешений «для ИИ» нет. Те же разрешения `api.pages.write`, `api.config.write`, `api.gpm.write` (и так далее), которые ограничивают любого потребителя API, ограничивают и ИИ.

Это значит, что вы управляете тем, что может делать ИИ, выбирая пользователя, которому выдан ключ:

- Если выдать ключ пользователю-суперадминистратору, ИИ получит полный доступ к сайту.
- Если выдать ключ пользователю только с разрешениями на страницы и медиафайлы, ИИ будет ограничен работой с контентом, без возможности менять конфигурацию, управлять пользователями или устанавливать пакеты.

> [!WARNING] Предупреждение
> Создайте отдельного пользователя с минимальными правами для доступа ИИ, а не используйте свою основную учётную запись администратора. Ключ никогда не может превысить разрешения пользователя, которому он принадлежит, поэтому учётная запись пользователя — ваша граница безопасности. Ограничение разрешений для отдельного ключа пока не применяется независимо от пользователя.

### Безопасность параллелизма

Вся запись конфигурации и страниц проходит через **оптимистичный контроль параллелизма на основе ETag** в API. Сервер читает `ETag` при `GET` и отправляет его обратно в `If-Match` при записи. Если ресурс за это время изменился (например, человек отредактировал ту же страницу в Admin2), API возвращает `409 Conflict` вместо молчаливой перезаписи, и агент должен заново получить данные и согласовать их.

### Наблюдаемость

Сервер MCP не добавляет собственный журнал аудита. Вместо этого каждая запись через API вызывает структурированное событие (`onApiPageCreated`, `onApiConfigUpdated` и остальные из семейства `onApi*`), а эти события питают систему **вебхуков** API. Чтобы записывать изменения, инициированные ИИ, направьте вебхук на свой эндпоинт журналирования или уведомлений. Доставки вебхуков подписываются HMAC, поэтому можно проверить их происхождение. Полный список событий см. в справочнике [События API](../../api/events/index.md).

## Разработка и поддержка

Для участников, работающих над самим сервером, в репозитории есть обычные скрипты:

```bash
npm run typecheck        # Проверка типов в исходниках TypeScript
npm test                 # Запуск набора модульных тестов
npm run build            # Компиляция в dist/
npm run audit:api        # Проверка покрытия инструментами работающего плагина API
npm run changelog:since  # Отчёт об изменениях плагина API с последней проверенной версии
```

Скрипты `audit:api` и `changelog:since` нужны, чтобы каталог инструментов оставался синхронизированным с развивающимся плагином API: они сравнивают аннотации `@api METHOD /path` сервера с фактическими маршрутами плагина.
