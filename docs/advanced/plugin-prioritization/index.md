# Приоритеты плагинов

Когда несколько плагинов слушают одни и те же хуки событий (подробности см. на [странице «Плагины > Хуки событий»](../../plugins/event-hooks/index.md)), различные обработчики выполняются в порядке «приоритета». Приоритет — это просто число. Чем больше число, тем раньше выполняется обработчик.

В редких случаях пользователям может понадобиться изменить приоритеты отдельных обработчиков. Это можно сделать, не трогая исходный код плагина.

Сначала точно определите, какие обработчики нужно изменить и как. Это продвинутая задача, требующая умения читать `.php`-файл плагина. Обычно хуки событий, функции-обработчики и приоритеты по умолчанию находятся в функции `onPluginsInitialized()` плагина.

Затем создайте файл `user/config/priorities.yaml`. Данные должны быть структурированы так:

```yaml
pluginName:
    eventName:
        handlerName: [integer]
```

Например, предположим, у вас есть плагин `essential`, который слушает событие `onPageInitialized`, вызывая функцию `handlePage` с приоритетом 0. И допустим, вы обнаружили, что приоритет должен быть `100`, чтобы функция выполнялась *до* другого плагина. Тогда добавьте в файл `user/config/priorities.yaml` следующее:

```yaml
essential:
    onPageInitialized:
        handlePage: 100
```
