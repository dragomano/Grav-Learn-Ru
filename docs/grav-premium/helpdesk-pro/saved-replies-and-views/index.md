# Сохранённые ответы и представления {: #saved-replies-and-views }

Три инструмента избавляют сотрудников от повторной работы: сохранённые ответы для часто отправляемого текста, сохранённые представления для часто открываемых списков и массовое редактирование для изменения многих заявок сразу.

## Личные и общие {: #personal-and-shared }

Сохранённые ответы и сохранённые представления существуют в двух наборах:

- **Личные**: видите только вы. Любой с `helpdesk-pro.desk` хранит свои.
- **Общие**: видит каждый сотрудник. Создание, изменение и удаление общих требуют `helpdesk-pro.library.manage`, поэтому тимлид поддерживает общий набор в порядке.

Общий ответ или представление, которое вы не можете изменить, всё равно показывается вам, но без Edit и Delete.

## Сохранённые ответы {: #saved-replies }

**Saved replies** (`#/saved-replies`, в разделе Library) перечисляет общие ответы и ваши, начиная с самых используемых.

### Создание сохранённого ответа {: #create-a-saved-reply }

1. Откройте **Saved replies** и выберите **New saved reply**.
2. Введите **title** и **text** (Markdown). Используйте [подстановки](#placeholders) для имени клиента и данных заявки.
3. Выберите, кто его видит (вы или команда) и в каком проекте он предлагается (во всех или в одном).
4. При желании выберите, что ещё он делает с заявкой, в разделе **When used, also** (см. [Макросы](#macros)).
5. Сохраните.

В заявке **Insert reply** рядом с **Attach files** перечисляет ответы, предлагаемые в проекте заявки, начиная с самых используемых. Начните печатать, чтобы искать по заголовкам и тексту; выберите ответ, и его текст попадёт в открытую вкладку редактора (Reply или Note) с уже заполненными подстановками, а **then set status** перейдёт к статусу ответа, если он задан. Отправка засчитывает использование ответа.

### Макросы {: #macros }

Сохранённый ответ, который также меняет заявку, — это макрос. В разделе **When used, also** выберите любое из:

- статус для установки («then set status» редактора)
- приоритет
- исполнителя: сотрудника, **Me** (кто использует макрос) или **Nobody**
- метки для добавления и метки для удаления
- проект для переноса
- тип (support, bug, feature)

Когда вы вставляете макрос, строка над текстом говорит, что он сделает до отправки («Also when sent: Assign to you; Add label Billing; Set priority to High»), с кнопкой **Leave the ticket as it is**, которая оставляет только текст. Статус идёт вместе с ответом; остальные изменения применяются сразу после отправки ответа от вашего имени, с обычной активностью, уведомлениями и обновлениями в реальном времени.

У макроса может вообще не быть текста: «Escalate» может только ставить Urgent и назначать тимлиду. Выбор такого макроса применяет его сразу, ничего не отправляя.

Изменение, названное макросом, но больше невозможное (архивный статус, метка или проект либо человек, который больше не сотрудник), тихо пропускается, а не останавливает ответ. [Правила](../rules-and-automations/index.md) тоже могут отправлять клиентам общие сохранённые ответы, но не их действия.

### Подстановки {: #placeholders }

Пишите подстановку в двойных фигурных скобках. Она заполняется из заявки при вставке ответа.

| Подстановка | Чем заполняется |
|---|---|
| `{{client.name}}` | Имя заявителя |
| `{{client.first_name}}` | Имя заявителя |
| `{{client.email}}` | Адрес электронной почты заявителя |
| `{{agent.name}}` | Ваше имя |
| `{{agent.first_name}}` | Ваше имя |
| `{{ticket.id}}` | Номер заявки, например 1042 |
| `{{ticket.subject}}` | Тема заявки |
| `{{ticket.status}}` | Статус заявки |
| `{{ticket.url}}` | Ссылка на обращение в справочном центре |
| `{{project.name}}` | Проект заявки |
| `{{site.name}}` | Название сайта |

У некоторых людей нет имени в записи, например у заявителя только с почтой. Укажите запасной вариант после черты: `Hi {{client.first_name | there}},` становится «Hi Ada,» или «Hi there,». Имя, которое на самом деле является адресом электронной почты, считается отсутствующим. Неизвестная Helpdesk Pro подстановка остаётся как написана, поэтому опечатка видна в черновике, а не исчезает.

## Сохранённые представления {: #saved-views }

Сохранённое представление — имя для набора фильтров и сортировки на All tickets.

1. Отфильтруйте и отсортируйте All tickets как нужно.
2. Выберите **Save view**, задайте имя и укажите, должна ли команда его видеть.

Ваши представления и общие появляются строкой ссылок над списком, а представление открывает список точно в сохранённом виде. Когда представление открыто, **Update view** сохраняет в него текущие фильтры, а **Delete view** удаляет его. Представление, отмеченное как представление по умолчанию, стоит первым.

Представление хранит собственные имена фильтров списка, поэтому представление с меткой, которая с тех пор удалена, всё равно открывается; отсутствующая метка отбрасывается.

## Массовое редактирование {: #bulk-edit }

1. На All tickets отметьте заявки (или установите флажок в заголовке для всей страницы).
2. Используйте полосу, появившуюся над списком: **Status**, **Assign**, **Priority**, **Project**, **Add label**, **Remove label** или **Delete** (с `helpdesk-pro.tickets.delete`).

За раз меняется до 200 заявок. Каждая заявка меняется отдельно, со своей активностью и проверками, поэтому заявка, которую вы не можете менять, пропускается, а остальные сохраняются. Рабочая область сообщает, сколько изменено и какие нет, с причиной.

Наблюдатели узнают о массовом изменении один раз. Колокольчик сворачивает то, что человек получил бы от него, в одно уведомление («Anna changed the status of 50 tickets to Waiting on client»), которое ссылается на All tickets и отправляется по почте не более одного раза.

## API и MCP {: #api-and-mcp }

| Маршрут | Право | Тело или запрос | Ответ |
|---|---|---|---|
| `GET /helpdesk-pro/saved-replies` | desk | `?project=&q=` | Ваши ответы и общие: `{id, title, body, project_id, shared, actions, usage_count, last_used_at, can_edit}` |
| `POST /helpdesk-pro/saved-replies` | desk (для общего нужно library.manage) | `{title, body, shared, project_id, actions}`; `actions` — `{status_id, priority, assignee_id, add_labels, remove_labels, project_id, kind}` (`assignee_id` — id сотрудника, `"me"` или `"none"`); `body` может быть пустым, если есть действия | `201` с ответом |
| `GET /helpdesk-pro/saved-replies/{id}` | desk | | Ответ, текст как написан |
| `PATCH /helpdesk-pro/saved-replies/{id}` | владелец или library.manage для общего | Любые поля создания | Ответ |
| `DELETE /helpdesk-pro/saved-replies/{id}` | владелец или library.manage для общего | | `204` |
| `POST /helpdesk-pro/saved-replies/{id}/render` | desk | `{ticket_id}` | `{id, title, body, actions, summary}` с заполненными подстановками; `actions` содержит только то, что ещё возможно |
| `POST /helpdesk-pro/saved-replies/{id}/apply` | desk и право редактировать заявку | `{ticket_id, with_status}` | Применяет действия макроса и отвечает заявкой |
| `GET /helpdesk-pro/saved-views` | desk | | `{id, name, filters, sort, order, columns, shared, is_default, can_edit}` |
| `POST /helpdesk-pro/saved-views` | desk (для общего нужно library.manage) | `{name, filters, sort, order, columns, shared, is_default}`; `filters` — объект или строка запроса фильтров списка | `201` с представлением |
| `PATCH /helpdesk-pro/saved-views/{id}` | владелец или library.manage для общего | Любые поля создания | Представление |
| `DELETE /helpdesk-pro/saved-views/{id}` | владелец или library.manage для общего | | `204` |
| `POST /helpdesk-pro/tickets/bulk` | desk (для удаления нужно tickets.delete) | `{ids, changes: {status_id, assignee_id, priority, kind, project_id, add_labels, remove_labels, delete}}` | `{updated: [ids], failed: [{id, reason}]}` |

`POST /helpdesk-pro/tickets/{id}/messages` принимает `saved_reply_id`, чтобы засчитать использование. Личный ответ или представление другого человека — `404`, как несуществующее.

Инструменты MCP: `list_saved_replies`, `get_saved_reply`, `create_saved_reply`, `update_saved_reply`, `delete_saved_reply`, `render_saved_reply`, `apply_saved_reply`, `list_saved_views`, `create_saved_view`, `update_saved_view`, `delete_saved_view` и `bulk_update_tickets`.
