# Проекты и права {: #projects-and-permissions }

Проекты определяют, кто что видит, а права — что могут делать сотрудники. Эта страница охватывает и то и другое, а также правила чтения и записи, которые из них следуют.

## Настройки проекта {: #project-settings }

Каждая заявка принадлежит одному проекту. Проектами управляют в рабочей области в разделе **Setup → Projects**, для этого нужно `helpdesk-pro.projects.manage`. В чистой установке есть один проект, **Support** (слаг `support`), публичный и требующий сортировки.

| Настройка | Значения | Что делает |
|---|---|---|
| Visibility | `private`, `members`, `groups`, `public` | Какие клиенты могут отправлять заявки и читать общие заявки проекта (см. ниже). По умолчанию `members`. |
| Staff access | `all`, `members` | `all`: с проектом работают все агенты. `members`: только агенты, добавленные участниками напрямую или через группу Grav. Администраторы в любом случае работают со всеми проектами. |
| Intake | `open`, `closed` | Могут ли клиенты открывать здесь новые заявки. Сотрудники всегда могут открыть заявку от имени клиента. |
| Triage required | вкл., выкл. | Когда включено, заявки из веб-формы или почты ждут в сортировке, прежде чем кто-то начнёт с ними работать. Заявки, созданные сотрудниками, никогда не ждут. |
| Default kind | `support`, `bug`, `feature` | Тип новой заявки, если клиент его не выбрал. |
| Default assignee | сотрудник | Принятые заявки назначаются этому человеку, если он работает с проектом. |
| Board | вкл., выкл. | Показывает проект как доску в рабочей области. |
| Email alias | адрес | Входящая почта на этот адрес открывает заявки в этом проекте, и ответы на его заявки уходят туда. |
| KB category | категория | Категория базы знаний, предлагаемая вместе с этим проектом. |

На странице проекта также хранятся его название и слаг. Она спрашивает перед уходом с несохранёнными изменениями.

Проект, в котором есть заявки, удалить нельзя. Вместо этого удаление архивирует его: архивный проект оставляет свои заявки доступными для чтения, но не принимает новые.

### Участники {: #members }

У проекта есть участники двух видов, каждый с ролью `agent` или `client`:

- **Люди**: конкретный сотрудник или клиент.
- **Группы Grav**: все в группе Grav. Членство в группе читается из учётной записи при каждом запросе, поэтому достаточно добавить человека в группу в Admin Next.

Участник с ролью `agent` работает с проектом `members`. Участник с ролью `client` может отправлять заявки и читать общие заявки проекта `members`; строка группы `client` делает то же для проекта `groups`. Роль клиента никогда не даёт доступ сотрудника.

## Права {: #permissions }

Права Helpdesk Pro — это действия доступа Grav 2.0. Выдавайте их группам Grav или отдельным учётным записям в Admin Next (**Accounts**, затем группа или пользователь, затем **Permissions**). Права, выданные через группы, учитываются. `api.super` считается обладателем всех прав Helpdesk Pro.

| Право | Что разрешает |
|---|---|
| `helpdesk-pro.desk` | Работать с заявками: рабочая область, чтение заявок и работа с ними в проектах, где вы работаете, собственные сохранённые представления и ответы, уведомления. Делает учётную запись сотрудником. |
| `helpdesk-pro.triage` | Принимать новые обращения, помечать их дубликатами или отклонять; объединять заявки. |
| `helpdesk-pro.tickets.delete` | Удалять и восстанавливать заявки, удалять сообщения, видеть удалённые заявки. |
| `helpdesk-pro.people.manage` | Добавлять и редактировать людей, отправлять ссылки для входа, блокировать, объединять и удалять людей. Создавать, редактировать и удалять организации и выбирать их участников. |
| `helpdesk-pro.library.manage` | Создавать и редактировать общие сохранённые ответы и общие сохранённые представления. |
| `helpdesk-pro.projects.manage` | Проекты, участники проектов, метки, статусы и пользовательские поля. |
| `helpdesk-pro.reports` | Экран отчётов и `GET /helpdesk-pro/reports`, сводку оценок, отчёт Helpdesk на странице отчётов Admin Next и виджет панели управления. Отчёты охватывают проекты, в которых работает учётная запись. |
| `helpdesk-pro.settings` | Настраивать Helpdesk Pro: настройки, правила, политики SLA, каналы уведомлений, экраны Email и Inbound log, перестроение поиска, отчёт о состоянии, безвозвратное удаление заявок. Делает учётную запись администратором, который работает со всеми проектами и может всё перечисленное выше. |

Сотрудникам также нужен `api.access`, без которого они вообще не попадут в Admin Next. Каждый с `helpdesk-pro.desk` может читать организации и переносить заявку, которую может редактировать, в другую организацию.

Рекомендуемые группы — `helpdesk-agents` (`api.access`, `helpdesk-pro.desk`, `helpdesk-pro.triage`) и `helpdesk-admins` (`api.access` и все перечисленные выше права). Helpdesk Pro никогда не создаёт группы сам.

### Сотрудники и клиенты {: #staff-and-clients }

Учётная запись считается **сотрудником**, когда у неё есть `helpdesk-pro.desk`, `helpdesk-pro.settings` или `api.super`, и **клиентом** в остальных случаях. Helpdesk Pro проверяет это при каждом запросе и записывает на человека, поэтому изменение в Admin Next вступает в силу при следующем запросе этого человека. Фоновая работа (письма, уведомления) использует последний известный ответ.

Статус сотрудника не открывает все проекты. То, с какими проектами работает агент, задаётся отдельно для каждого проекта через **Staff access** и участников. Администраторы работают со всеми проектами.

### Ключи API с областями доступа {: #api-keys-with-scopes }

Ключ API, созданный со списком областей доступа, ограничен этими областями, и Helpdesk Pro применяет то же ограничение к своим проверкам. Ключ с областью `helpdesk-pro.desk` не может удалять заявки, даже если его владелец — администратор.

## Кто может читать заявку {: #who-may-read-a-ticket }

**Клиент** может читать заявку (её публичные ответы и публичную активность, но никогда заметки), когда она не удалена и:

1. он её заявитель или копия, независимо от проекта, или
2. область видимости заявки — `project`, и он может читать общие заявки проекта, или
3. заявка принадлежит его [организации](../organizations/index.md), и организация делится заявками. Такие коллеги только читают.

Правило 2 следует видимости проекта:

| Видимость проекта | Кто из клиентов может отправлять | Гости могут отправлять | Кто из клиентов читает заявки с областью `project` |
|---|---|---|---|
| `private` | никто (трекер только для сотрудников) | нет | никто |
| `members` | клиенты-участники (люди или строки групп) | нет | клиенты-участники |
| `groups` | клиенты в группе Grav с ролью `client` | нет | эти клиенты |
| `public` | любой вошедший клиент | когда включён `portal.guest_submissions` | любой вошедший клиент |

**Сотрудники** могут читать каждую заявку, включая заметки, в проектах, где работают. Сотрудник, который является заявителем заявки в проекте, где он не работает, читает её как клиент: только публичные сообщения.

**Удалённые заявки** скрыты от всех, кроме сотрудников с `helpdesk-pro.tickets.delete`, которые могут их восстановить. Ничто не удаляет заявку безвозвратно по таймеру; это может сделать только администратор из рабочей области.

Тому, кто не может читать заявку, сообщают, что её не существует («not found»), а не «forbidden», поэтому никто не может проверять, какие номера заявок используются.

## Что кому можно делать {: #what-people-may-do }

| Действие | Кто |
|---|---|
| Ответить | Сотрудники, работающие с проектом; любой клиент, который может читать заявку по правилу 1 или 2 выше. Коллега, который читает её только через организацию, не может ответить, пока его не добавят в копию. |
| Добавить заметку | Сотрудники, работающие с проектом |
| Менять статус, приоритет, тип, тему, метки, область видимости | Сотрудники, работающие с проектом |
| Отметить решённой, открыть снова | Заявитель и копии (только из статусов по умолчанию resolved и open и обратно; закрытое обращение остаётся закрытым) |
| Назначить | Сотрудники, работающие с проектом, — другому человеку, который с ним работает |
| Перенести в другой проект | Сотрудники, работающие с обоими проектами |
| Перенести в другую организацию | Сотрудники, работающие с проектом |
| Добавлять и убирать копии и наблюдателей | Сотрудники, работающие с проектом; любой может убрать себя |
| Отключить уведомления | Любой, кто может читать заявку, кроме коллеги, который читает её только через организацию |
| Принять, отклонить, пометить дубликатом, объединить | Сотрудники с `helpdesk-pro.triage` |
| Удалить и восстановить | Сотрудники с `helpdesk-pro.tickets.delete` |
| Удалить безвозвратно | Администраторы (`helpdesk-pro.settings`) |

Ответ клиента двигает заявку: решённая заявка открывается снова, а «waiting on client» становится «waiting on us». Первый публичный ответ сотрудника открывает новую заявку, а ответ может одновременно задать любой статус.

## Внутренние заметки остаются внутренними {: #internal-notes-stay-internal }

Заметки скрыты от клиентов на всех уровнях, а не только спрятаны на странице:

- Каждый запрос сообщений, который выполняет страница, письмо или канал для клиентов, просит у базы только публичные сообщения. Единственный запрос, возвращающий заметки, отказывает всем, кто не сотрудник.
- Каждое событие сообщает, `public` оно или `internal`, а системы уведомлений, почты и обновлений в реальном времени доставляют внутренние события только сотрудникам, работающим с проектом.
- Вложения в заметке так же приватны, как сама заметка.
