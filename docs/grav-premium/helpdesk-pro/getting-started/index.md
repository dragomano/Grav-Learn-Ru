# Начало работы {: #getting-started }

Эта страница проведёт от чистой установки до работающей службы поддержки: справочный центр на сайте, проект и первая заявка, отвеченная из рабочей области. В конце объясняются термины, которые Helpdesk Pro использует повсюду.

## Перед началом {: #before-you-begin }

- Helpdesk Pro установлен, а ваши сотрудники входят в группу `helpdesk-agents` или `helpdesk-admins` (см. [Установку](../installation/index.md)).
- Плагин Email умеет отправлять почту (`bin/plugin email test-email --to=you@example.com`).

## Создание страницы справочного центра {: #create-the-help-center-page }

Справочный центр — входная дверь клиентского портала. Он расположен по маршруту страницы Grav с типом **Help Center**.

1. В Admin Next добавьте страницу верхнего уровня и выберите тип страницы **Help Center**.
2. Задайте заголовок, например «Help», и короткий приветственный текст. Он отображается в верхней части справочного центра.
3. Опубликуйте страницу.

Маршрут страницы становится адресом справочного центра, обычно `/help`, и все страницы портала находятся под ним: `/help/new`, `/help/tickets` и так далее. Нумерованная папка также добавляет пункт **Help** в меню вашей темы. Об остальном см. в разделе [Справочный центр и портал](../help-center-and-portal/index.md).

Без страницы Help Center портал всё равно работает по адресу `portal.route` (по умолчанию `/help`) внутри временной страницы — этого достаточно для первого знакомства.

## Настройка первого проекта {: #set-up-your-first-project }

Каждая заявка принадлежит проекту. В чистой установке есть один проект — **Support** (слаг `support`), публичный и требующий сортировки.

1. Откройте **Helpdesk** в боковой панели Admin Next.
2. Перейдите в **Setup → Projects** и откройте **Support**.
3. Проверьте **Visibility** (кто может отправлять обращения), **Staff access** (кто с ними работает) и то, ждут ли новые обращения в **Triage**.
4. При желании выберите **Default assignee**, чтобы принятые заявки попадали к конкретному человеку.
5. Сохраните.

[Проекты и права](../projects-and-permissions/index.md) объясняют каждую настройку проекта.

## Отправка первого обращения {: #send-your-first-request }

1. Откройте `/help/new` в окне приватного режима как гость.
2. Укажите имя, адрес электронной почты, который вы можете прочитать, краткое описание и сообщение.
3. Отправьте обращение.

Обращение создаётся, вы получаете письмо «We got your request» со ссылкой для входа, и ссылка открывает обращение уже с выполненным входом. Поскольку проект Support требует сортировки, заявка ждёт в очереди **Triage** рабочей области.

## Ответ из рабочей области {: #answer-it-from-the-desk }

1. В рабочей области откройте **Triage**, затем обращение.
2. Выберите **Accept**. Оставьте исполнителя пустым, чтобы использовать значение проекта по умолчанию, или выберите человека.
3. Откройте заявку. Напишите ответ на вкладке **Reply** и нажмите **Send reply**.

Клиенту отправляется письмо с ответом, и он видит ответ на странице своего обращения. Чтобы оставить комментарий, который увидят только сотрудники, используйте вкладку **Note**. Об остальном на экране заявки см. в разделе [Рабочая область сотрудников](../the-desk/index.md).

## Термины Helpdesk Pro {: #the-words-helpdesk-pro-uses }

Эти слова означают одно и то же везде: в рабочей области, портале, API и документации.

| Термин | Значение |
|---|---|
| Заявка (Ticket) | Одно обращение: тема, переписка, статус, приоритет, один заявитель, не более одного исполнителя, метки, тип (support, bug или feature) и проект. Клиенты видят её как «запрос». Её id — номер, который видят сотрудники (`#1042`). |
| Ответ (Reply) | Публичное сообщение в заявке. Заявитель и клиенты в копии могут его прочитать и получают его по почте. |
| Заметка (Note) | Внутреннее сообщение. Его видят только сотрудники, работающие с проектом заявки. Никогда не отправляется клиентам и не показывается в портале. |
| Активность (Activity) | Запись изменений только для добавления: статус, исполнитель, приоритет, метки, проект и так далее. Большая часть активности внутренняя; решение, закрытие, повторное открытие, отклонение и объединение публичны. |
| Проект (Project) | Очередь, которая группирует заявки и определяет, кто может их видеть и отправлять. |
| Человек (Person) | Любой, кого знает Helpdesk Pro: сотрудники, клиенты с учётной записью Grav и люди, которые только писали по почте. |
| Заявитель (Requester) | Человек, для которого создана заявка. Ровно один на заявку. |
| Копия (Cc) | Клиент, добавленный в заявку. Он читает публичные сообщения и отвечает на них так же, как заявитель. |
| Наблюдатель (Watcher) | Сотрудник, следящий за заявкой. Сотрудники начинают наблюдать, когда участвуют в заявке, но никогда — за целым проектом. |
| Агент (Agent) | Сотрудник, работающий с заявками: `api.access` плюс `helpdesk-pro.desk`. |
| Администратор (Admin) | Сотрудник, настраивающий Helpdesk Pro: `helpdesk-pro.settings` или `api.super`. |
| Клиент (Client) | Человек без прав сотрудника. Пользуется только порталом и почтой. |
| Гость (Guest) | Посетитель, который не вошёл на сайт. |
| Статус (Status) | Именованное состояние внутри одной из шести фиксированных категорий. |
| Категория статуса (Status category) | Одна из `new`, `open`, `waiting_client`, `waiting_us`, `resolved`, `closed`. Отчёты, уведомления и формулировки для клиентов читают категорию, а не название статуса. |
| Сортировка (Triage) | Очередь, где новое обращение ждёт принятия, пометки дубликатом или отклонения. |
| Канал (Channel) | Как пришла заявка: `web`, `email`, `staff` или `api`. |
| Область видимости (Visibility scope) | Какие клиенты могут читать заявку: `requester` (заявитель и копия, по умолчанию) или `project` (каждый клиент, который может читать общие заявки проекта, для публичных баг-трекеров). |
| Пользовательское поле (Custom field) | Дополнительный вопрос к заявке, например номер заказа. См. [Пользовательские поля](../custom-fields/index.md). |

## Люди и учётные записи Grav {: #people-and-grav-accounts }

У сотрудников всегда есть учётные записи Grav, поскольку они входят в Admin Next. Клиент получает учётную запись Grav только при входе в портал. Тот, кто только пишет по почте или пользуется гостевой формой, остаётся человеком в базе Helpdesk Pro без учётной записи Grav, поэтому `user/accounts` растёт только теми, кто пользуется порталом.

Учётная запись связывается с человеком по ключу хранения учётной записи, который не меняется при редактировании имени пользователя. При каждом запросе Helpdesk Pro копирует человеку тип учётной записи (сотрудник или клиент), его права Helpdesk Pro и группы Grav. Повышение клиента до сотрудника или отзыв рабочей области у агента вступают в силу при следующем запросе.

- **Ранние обращения.** Когда тот, кто раньше писал по почте, входит с учётной записью на тот же адрес, его ранние обращения присоединяются к учётной записи только после подтверждения адреса. См. [Ссылки для входа](../sign-in-links/index.md#earlier-requests).
- **Удалённые учётные записи.** Удаление учётной записи Grav никогда не удаляет человека или его заявки. Человек сохраняет старый ключ как маркер удаления и теряет связь, а новая учётная запись с тем же именем ничего не наследует, пока не подтвердит адрес.
- **Заблокированные люди.** Заблокированный человек может читать свои существующие заявки, но не может отправлять обращения, отвечать через сайт или почту, запрашивать ссылки для входа и не получает уведомлений.

## Как пишутся сообщения {: #how-messages-are-written }

Ответы и заметки пишутся в Markdown. Каждое сообщение преобразуется в HTML при сохранении (и снова при редактировании), необработанный HTML экранируется, действует строгий список разрешённых тегов, а для поиска, почты и предпросмотра сохраняется текстовая копия. Переносы строк учитываются, поэтому текст, набранный так, как люди пишут письма, отображается именно так.

Сотрудники могут упомянуть коллегу через `@username` (его имя пользователя Grav в нижнем регистре) в ответе или заметке. Упоминать можно только сотрудников, и упоминания ищутся только в сообщениях сотрудников. Упомянутый коллега начинает следить за заявкой.
