# Статусы и метки {: #statuses-and-labels }

Статусы показывают, на каком этапе находится заявка, а метки помечают её для фильтрации и отчётов. И тем и другим управляют сотрудники с правом `helpdesk-pro.projects.manage` в рабочей области.

## Категории статусов {: #status-categories }

Каждый статус принадлежит одной из шести фиксированных категорий. Категории никогда не меняются; именно их читают отчёты, уведомления, часы SLA и формулировки для клиентов.

| Категория | Значение | Что видят клиенты |
|---|---|---|
| `new` | Ещё никто не смотрел | Received |
| `open` | В работе | In progress |
| `waiting_client` | Ждём ответа клиента | Waiting for your reply |
| `waiting_us` | Клиент ответил; ответственность на сотрудниках | In progress |
| `resolved` | Решена; клиент ещё может открыть её снова | Solved |
| `closed` | Завершена окончательно | Closed |

В чистой установке есть один статус на категорию (New, Open, Waiting on client, Waiting on us, Resolved, Closed), и каждый является статусом по умолчанию для своей категории.

## Управление статусами {: #manage-statuses }

**Setup → Statuses** (`#/setup/statuses`) — одна таблица, сгруппированная по категориям, с числом заявок, использующих каждый статус (ссылка на эти заявки). Переходов и рабочего процесса нет: любой статус может следовать за любым другим.

- **Add status** запрашивает категорию, название и цвет. Например, добавьте «Waiting on vendor» в `waiting_client`.
- Переименовывайте статусы, меняйте их цвет и перемещайте вверх и вниз внутри категории.
- Выбирайте статус по умолчанию для каждой категории. Он отмечается только там, где в категории больше одного статуса.
- Архивируйте статус, который больше не используется, или удаляйте его.

Эти правила сохраняют историю честной:

- В каждой категории всегда ровно один статус по умолчанию и как минимум один статус.
- Категорию статуса можно изменить, только пока её не использует ни одна заявка. Вместо этого добавьте новый статус.
- Удаление статуса, который используется заявками, требует выбрать другой статус той же категории для их переноса.
- Архивный статус не может быть статусом по умолчанию и не может быть выбран для заявки. Заявки, уже находящиеся в нём, сохраняют его.

## Что записывает изменение статуса {: #what-a-status-change-records }

Каждая заявка хранит факты, нужные отчётам и SLA: когда её статус последний раз менялся, сколько всего времени она провела в ожидании клиента, когда её последний раз решали и закрывали, сколько раз открывали заново и когда сотрудники впервые ответили. Эти данные записываются по мере событий и не могут быть восстановлены задним числом.

Изменения статуса — внутренняя активность, кроме входа в `resolved` или `closed` и выхода из них: их клиент видит в своём обращении.

## Автоматические изменения {: #automatic-changes }

- Первый публичный ответ сотрудника на заявке в `new` переводит её в статус по умолчанию `open`, если только сам ответ не задаёт статус.
- Ответ клиента на заявку в `resolved` открывает её снова (по умолчанию `open`), а ответ на заявку в `waiting_client` переводит её в статус по умолчанию `waiting_us`.
- Клиент может отметить своё обращение решённым (статус по умолчанию `resolved`) и открыть его снова, пока оно решено. Заявку в `closed` нельзя открыть или ответить на неё; портал предлагает создать новую.

## Метки {: #labels }

Метка может быть глобальной (доступной во всех проектах) или принадлежать одному проекту. Названия уникальны внутри проекта и среди глобальных меток.

**Setup → Labels** (`#/setup/labels`) создаёт, переименовывает, перекрашивает, архивирует и удаляет метки. Название метки открывает заявки, которые её несут. Удаление метки убирает её со всех заявок.

- Слаг метки задаётся при создании и никогда не меняется, поэтому переименование «Billing» в «Invoices» сохраняет работу всего, что ищет метку по слагу.
- Перенос заявки в другой проект удаляет метки старого проекта и сохраняет глобальные.

## API и MCP {: #api-and-mcp }

| Маршрут | Право | Запрос | Ответ |
|---|---|---|---|
| `GET /helpdesk-pro/statuses` | desk | `archived=1` | `{new: [...], open: [...], waiting_client: [...], waiting_us: [...], resolved: [...], closed: [...]}`, каждый статус `{id, name, category, color, slug, position, is_default, archived, tickets}` |
| `POST /helpdesk-pro/statuses` | projects.manage | `{category, name, color}` | `201` со статусом |
| `POST /helpdesk-pro/statuses/reorder` | projects.manage | `{category, ids}` | `204` |
| `PATCH /helpdesk-pro/statuses/{id}` | projects.manage | `{name, color, is_default, archived, category}` (категорию — только пока статус не используется) | Статус |
| `DELETE /helpdesk-pro/statuses/{id}` | projects.manage | `move_to_id` (в запросе или теле), обязателен, если статус используется заявками | `204` |
| `GET /helpdesk-pro/labels` | desk | `project`, `archived=1` | Глобальные метки и метки проектов, в которых вы работаете; с `project` — то, что может нести заявка в этом проекте |
| `POST /helpdesk-pro/labels` | projects.manage | `{name, color, description, project_id}` (без `project_id` для глобальной метки) | `201` с меткой; `409`, если имя занято |
| `PATCH /helpdesk-pro/labels/{id}` | projects.manage | `{name, color, description, position, archived}` | Метка |
| `DELETE /helpdesk-pro/labels/{id}` | projects.manage | | `204`. Метка снимается со всех заявок |

Инструменты MCP: `list_statuses`, `create_status`, `reorder_statuses`, `update_status`, `delete_status`, `list_labels`, `create_label`, `update_label` и `delete_label`.
