# Рабочая область сотрудников {: #the-staff-desk }

Сотрудники работают с заявками в Admin Next на странице **Helpdesk** в боковой панели. Эта страница — экскурсия: экраны, поиск заявок, работа с одной заявкой, доски и сочетания клавиш.

Для открытия рабочей области нужно `helpdesk-pro.desk` (см. [Проекты и права](../projects-and-permissions/index.md)). Она находится по адресу `/admin/plugin/helpdesk-pro`, следуя маршруту вашего Admin Next.

## Экраны {: #screens }

Всё происходит на одной странице. У каждого экрана свой адрес после `#` (например, `#/tickets?category=open`), поэтому отфильтрованный список или заявка — ссылка, которую можно добавить в закладки или отправить коллеге, а кнопка Back браузера проходит по тому, что вы смотрели.

| Адрес | Экран | Для чего |
|---|---|---|
| `#/my-work` | My work | Заявки, назначенные вам, сгруппированные по тому, что нужно: **Needs your reply** (последним говорил клиент, сначала старые), **In progress**, **Waiting on client** (со временем ожидания) и **Recently solved** (последние 7 дней). Когда вам ничего не назначено, экран предлагает неназначенные заявки. |
| `#/tickets` | All tickets | Каждая заявка, которую вы можете читать, с поиском, сортировкой и чипами фильтров. |
| `#/tickets/new` | New ticket | Открыть заявку самому — для клиента или для себя. |
| `#/t/<id>` | Ticket | Одна заявка: переписка, редактор и детали. |
| `#/board/<project>` | Board | Заявки проекта карточками в колонке на статус. |
| `#/triage` | Triage | Обращения, ждущие принятия, пометки дубликатом или отклонения. См. [Сортировка и объединение](../triage-and-merging/index.md). |
| `#/notifications` | Notifications | Всё, что сказал колокольчик, начиная с нового, с **Mark read** и **Mark all read**. |

| `#/reports` | Reports | Цифры за период для тех, у кого есть `helpdesk-pro.reports`. См. [Отчёты](../reports/index.md). |

| `#/setup/projects` | Projects | Проекты и страница на каждый проект. |
| `#/setup/statuses` | Statuses | Шесть категорий и статусы в каждой. См. [Статусы и метки](../statuses-and-labels/index.md). |

Вы видите только экраны, которые разрешают ваши права. Адрес без экрана за ним (опечатка в ссылке, старая закладка) открывает My work с короткой заметкой об этом.

Каждый экран запрашивает данные при открытии, начинается сверху, а Back возвращает вас туда, где вы прокрутили. Нажатие пункта бокового меню текущего экрана загружает его заново, как и возвращение на вкладку браузера через некоторое время (если нет несохранённых изменений).

Рабочая область открывается на экране из `desk.default_view` (`my-work` или `tickets`). Значок рядом с **Helpdesk** в боковой панели Admin Next считает обращения, ждущие в сортировке (для тех, кто сортирует), плюс ваши назначенные заявки, требующие ответа. My work называет то же число сверху.

## Боковое меню {: #the-side-menu }

Экраны располагаются в пяти разделах: **Work** (My work, All tickets, Notifications, Triage, Ratings, Reports), **Library** (Saved replies, People, Organizations), **Automation** (Rules, SLA, Channels), **Setup** (Projects, Statuses, Labels, Fields) и **Operations** (Search, Email, Inbound log, System). Раздел без доступных вам экранов опускается.

- Нажмите заголовок раздела, чтобы открыть или закрыть его. При включённом **One section at a time** (по умолчанию, под меню) открытие раздела закрывает остальные.
- Булавка рядом с заголовком (появляется при наведении) держит раздел открытым.
- Раздел с текущим экраном всегда открыт при переходе.
- Закрытый раздел показывает счётчик, когда что-то внутри требует внимания: ваши заявки, требующие ответа, непрочитанные уведомления, обращения в сортировке, неудачная и задержанная почта в Inbound log или сбойные каналы. Наведите на счётчик, чтобы увидеть, из чего он складывается.
- **Find a screen** сверху фильтрует меню по мере ввода.
- « сворачивает меню в узкую колонку значков; » снова открывает его.

При ширине меньше 900px меню находится над экраном во всю ширину и не сворачивается. Браузер запоминает свёрнутое меню, открытые разделы, булавки и переключатель (`helpdesk-pro.nav.rail` и `helpdesk-pro.nav.bands` в локальном хранилище). Кнопка **Settings** вверху страницы открывает страницу настроек плагина.

## Поиск заявок {: #finding-tickets }

На All tickets каждая строка чипов фильтрует одно: категорию статуса, исполнителя (Me, Unassigned или человек), приоритет, проект, тип и метку. Чипы одной строки совпадают по любому из них; чипы разных строк сужают список. Число на чипе считает каждую заявку, которая совпала бы во всём результате, а не только на странице. Чип без заявок скрыт, а строка с одним выбором опускается.

**More filters** под чипами содержит фильтры без счётчиков: канал, по которому пришла заявка, [организацию](../organizations/index.md) (когда на сайте есть организации) и [пользовательские поля](../custom-fields/index.md), по которым можно фильтровать. В свёрнутом виде заголовок говорит, что задано внутри («More filters · Channel: Email · Plan: Pro»). **Unread** оставляет заявки с активностью, которую вы не видели. SLA добавляет чипы **Breached** и **Due soon**, когда [SLA](../sla/index.md) включён.

Сортировка предлагает недавно обновлённые, новые, приоритет, дольше всех ждущие (клиент, ждущий дольше всех, первым) и при SLA — ближайший срок.

### Поиск {: #searching }

Поле поиска на All tickets (`/` переходит к нему) находит заявку по номеру (`1042` или `#1042`), теме, имени или адресу электронной почты заявителя и словам переписки, включая внутренние заметки. 100 лучших совпадений поискового индекса добавляются к совпадениям по теме, после чего чипы, сортировка и страницы работают с этим набором. Заявка, найденная по одной из заметок, говорит **Matched in an internal note** под темой. Заметки проектов, где вы не работаете, никогда не ищутся для вас.

### Список {: #the-list }

Столбцы, которые говорили бы одно и то же в каждой строке, скрыты: на сайте с одним проектом нет столбца Project, а в списке, отфильтрованном по вашим заявкам, нет столбца Assignee. На узком экране первыми уходят наименее полезные столбцы: Project, Labels и столбцы пользовательских полей, затем Priority и Updated, затем Assignee.

Тема каждой строки открывает заявку. **Assign to me** находится в строке; **Mark resolved** и **Delete** — в меню ⋯. Число совпавших заявок указано под заголовком, а страницы появляются, только когда их больше одной. Отмечайте строки, чтобы [изменить много заявок сразу](../saved-replies-and-views/index.md#bulk-edit).

## Открытие заявки вручную {: #open-a-ticket-yourself }

**New ticket** на All tickets и My work предназначена для обращения, пришедшего другим путём, например по телефону или в чате.

1. Выберите **Project** (тот, где вы работаете).
2. Выберите **Requester**: ищите по имени или почте. Полный адрес, которого ещё ни у кого нет, создаёт человека с необязательным именем. Оставьте пустым, чтобы открыть заявку от себя.
3. Напишите **Subject** и **First message**.
4. Задайте **Kind**, **Priority** и **Assignee** (пусто использует исполнителя проекта по умолчанию).
5. Оставьте **Email the requester** отмеченным, чтобы отправить первое сообщение как письмо от вас со ссылками на файлы и ссылкой на обращение.
6. При необходимости прикрепите файлы и заполните пользовательские поля проекта.
7. Создайте заявку.

Заявки, открытые здесь, пропускают сортировку. В переписке первое сообщение читается «Anna on behalf of Maria Lopez», поэтому никто не примет его за слова клиента. Сотрудники могут задать здесь любое пользовательское поле, включая поля только для сотрудников, и ни одно не обязательно.

## Работа с заявкой {: #work-a-ticket }

Заголовок показывает тему (нажмите, чтобы переименовать заявку), номер, проект, как она пришла и кто спросил, а рядом — статус, приоритет и тип. Каждое изменение сохраняется сразу. Меню ⋯ содержит **Rename** и **Merge into another ticket…**.

Переписка читается сверху вниз. Открытие заявки отмечает её прочитанной и отмечает прочитанными ваши уведомления о ней, поэтому они никогда не приходят вам по почте. Ответы — обычные карточки; внутренние заметки имеют подсвеченный фон и метку **Note**; изменения появляются маленькими строками между сообщениями. Сообщение, пришедшее по почте, говорит «via email» и имеет **Show original**, который открывает письмо в полученном виде. Файлы перечислены под своим сообщением, изображения — миниатюрами.

### Ответ или заметка {: #reply-or-note }

У редактора внизу две вкладки:

- **Reply** уходит клиенту. Оно отправляется заявителю по почте и показывается в его обращении. Кнопка говорит **Send reply**, а строка над редактором называет получателей.
- **Note** остаётся у сотрудников. Редактор меняет цвет заметки, строка над ним говорит, что её видят только сотрудники, а кнопка говорит **Add note**.

У каждой вкладки свой черновик, сохраняемый в браузере по мере ввода. Уход из заявки с неотправленным черновиком спрашивает подтверждения; **Discard changes** удаляет черновик и все загруженные для него файлы. Cmd+Enter (Ctrl+Enter) отправляет.

Рядом с кнопкой отправки **then set status** меняет статус на том же шаге. После ответа он начинается с «waiting on client» по умолчанию; после заметки сохраняет текущий статус.

Рядом с **Attach files** кнопка **Insert reply** выбирает один из ваших [сохранённых ответов](../saved-replies-and-views/index.md), а **Insert article** ищет по базе знаний и вставляет ссылку на статью в текст. В обеих стрелки перемещают, Enter выбирает, Escape закрывает.

### Когда кто-то ответил, пока вы писали {: #when-someone-replied-while-you-were-writing }

Если во время вашего письма приходит новое публичное сообщение (ответил клиент или коллега), отправка не проходит. Новые сообщения появляются над черновиком с двумя вариантами: **Edit first** вставляет их в переписку, чтобы вы поправили текст, а **Send anyway** отправляет как есть. Это работает с обновлениями в реальном времени и без них.

Изменения полей защищены так же. Если кто-то изменил заявку с момента её открытия, ваше изменение не применяется, заявка перезагружается, и вы можете проверить, что изменилось, перед новой попыткой.

### Боковая панель {: #the-side-panel }

- **Details**: исполнитель (с **Assign to me**), проект, метки (добавляйте из списка, удаляйте через ×) и то, могут ли читать заявку только заявитель и копии или все в проекте.
- **People**: заявитель со ссылками на другие его заявки и страницу человека и, для клиентов, **Send sign-in link**; все в копии; и сотрудники-наблюдатели. **Watch**, **Stop watching** и **Mute** применяются к вам; **Remove** убирает кого-то другого.
- **Organization**: организация заявки со ссылкой и **Change**. Скрыта на сайте без организаций.
- **Fields**: пользовательские поля, применимые к проекту заявки. Нажмите значение или **Add**, чтобы изменить его на месте.
- **SLA**: политика, обе цели с их сроками и то, выполнена ли каждая или нарушена.
- **Rating**: ответ клиента на «How did we do?», пока он есть у заявки.
- **Triage** появляется только у заявки, всё ещё ждущей там, **Before writing in** — только когда обращение началось в справочном центре, а **Similar tickets** — только когда они есть.

## Доски {: #boards }

Проект с включённой настройкой **Show a board for this project** (Setup → Projects) получает доску по `#/board/<project-slug>`. Досок нет в боковом меню: All tickets показывает переключатель **List | Board**, когда доска подходит. Без фильтра проекта Board открывает единственную доску или список для выбора. Доски видят только сотрудники. Установите `desk.board` в `false`, чтобы выключить все доски.

У доски есть колонка на каждый статус в порядке категорий: New, Open, Waiting on us, Waiting on client и Resolved. Категория с несколькими статусами получает заголовок над своими колонками. Пустая колонка сворачивается в узкую полосу со счётчиком и открывается, пока вы перемещаете карточку. Карточки сортируются по приоритету, затем по последней активности. Каждая карточка показывает номер и тему, кто спросил, инициалы исполнителя, приоритет, если он не Normal, метку Bug или Feature и метки. Колонка показывает до 50 карточек и ссылается на полный список, когда их больше.

Колонка Closed скрыта, пока вы не нажмёте **Show closed**. Выбор входит в адрес (`?closed=1`), как и чипы фильтров над доской.

### Перемещение карточек {: #move-cards }

Перетащите карточку в другую колонку, чтобы изменить статус заявки на статус этой колонки. Изменение сохраняется сразу и появляется в активности заявки. Нажатие карточки без перемещения открывает заявку.

С клавиатуры каждая карточка — точка табуляции. Стрелки перемещают между карточками, Enter открывает заявку. Пробел поднимает карточку; левая и правая стрелки выбирают колонку, Space или Enter опускает её, Escape возвращает. Каждый шаг озвучивается скринридерам.

Если кто-то изменил заявку после загрузки доски, перемещение не применяется. Карточка перезагружается там, где она на самом деле, с заметкой об этом.

## Сочетания клавиш {: #keyboard-shortcuts }

Нажмите `?` в любом месте рабочей области, чтобы увидеть список. Сочетания — одиночные клавиши, никогда не с Cmd, Ctrl или Alt, поэтому собственные клавиши Admin Next продолжают работать. Они не срабатывают во время ввода и ждут, пока открыт диалог.

| Клавиши | Где | Что делают |
|---|---|---|
| `c` | Везде | Новая заявка (на доске — в проекте этой доски) |
| `/` | Везде | Поиск заявок |
| `g`, затем `m`, `t`, `r`, `n` или `b` | Везде | My work, All tickets, Triage, Notifications, доска |
| `j` / `k` | Списки и доски | Следующая и предыдущая заявка |
| Enter или `o` | Списки и доски | Открыть заявку |
| `a` | Списки, доски, заявка | Назначить заявку мне |
| `e` | Списки, доски, заявка | Отметить заявку решённой |
| `r` / `n` | Заявка | Написать ответ / внутреннюю заметку |
| `s` | Заявка | Изменить статус |
| `l` | Заявка | Добавить метку |
| `?` | Везде | Показать лист сочетаний |

В сортировке с открытым обращением `a`, `d` и `x` запускают Accept, Duplicate of… и Decline. Одиночные сочетания можно отключить для вашего браузера переключателем в листе `?`; `?` продолжает работать, чтобы их можно было вернуть.

## Виджет панели управления {: #the-dashboard-widget }

Панель управления Admin Next получает виджет **Helpdesk** для сотрудников: обращения, ждущие в сортировке, неназначенные открытые заявки, ваши заявки, требующие ответа, и сколько ждёт самая старая заявка «waiting on us». Каждое число открывает рабочую область на этом списке. Установите `admin2.dashboard` в `false`, чтобы выключить его.

**Tools → Reports** в Admin Next включает отчёт Helpdesk для учётных записей с `helpdesk-pro.reports`. См. [Отчёты](../reports/index.md#admin-next-s-reports-page).
