# Интерфейс Algolia Pro {: #algolia-pro-frontend }

Настройка интерфейса привязана к индексам Algolia Pro; глобальных настроек для них нет. Однако благодаря мощному механизму настройки Algolia Pro вы можете менять эти параметры для отдельных страниц, а дочерние страницы могут наследовать набор настроек родительской.

Чтобы попасть в эти настройки, откройте пункт меню **Algolia Pro**, затем на вкладке **Algolia Indexes** выберите один из перечисленных индексов.

В конце страницы настройки вы найдёте раздел **User Interface Parameters**.

#### Параметры интерфейса {: #user-interface-parameters }

`![Настройка интерфейса](frontend-options-1.png?classes=shadow)`

- **Built-in CSS Style** → Загружать ли встроенный CSS (~15 КБ / ~3,68 КБ в gzip)
- **Debounce Search** → Добавляет задержку `250ms` между поисковыми запросами. Это помогает довольно сильно сократить число операций поиска в Algolia. Минус в том, что интерфейс может ощущаться чуть менее отзывчивым. Когда выключено, поиск идёт сразу по мере ввода, но это существенно увеличивает число операций поиска в Algolia. Большинство сайтов справляется с мгновенным поиском, поэтому Algolia Pro поставляется с выключенным Debounce по умолчанию.
- **Accent Color** → Меняет акцентный цвет интерфейса. Это включает курсор в поле, выделенный текст, выбранную вкладку пагинации и строку выбранного результата.
  (По умолчанию: <span class="color-swatch" style="background-color:#3b82f6"></span> `#3b82f6`).
- **Appearance** → Стиль оформления всего интерфейса. Может быть **Light**, **Dark** или **System**. В режиме System (по умолчанию) он автоматически переключается между Light и Dark по настройкам операционной системы клиента.
- **Results Statistics** → Показывает статистику результатов поиска для запроса (например, _428 results found in 7m_).
  ! Использует [виджет `<ais-stats>`](https://www.algolia.com/doc/api-reference/widgets/stats/vue/?target=_blank) в [шаблоне hits.html.twig](#override-templates)
- **Display Subtitle (TOC Anchor)** → Когда включено и используется [Page TOC](../backend/index.md#page-toc-plugin-for-better-results), заголовок результатов показывается с подзаголовком-якорем в скобках. Этот параметр позволяет показывать или скрывать подзаголовок.
- **Warm Connection** → По умолчанию Algolia автоматически выполняет начальный поиск в фоне, как только загружается страница. Это ускоряет последующие запросы пользователей, потому что заранее убирает разрешение DNS, рукопожатие SSL, предварительную загрузку API и так далее. Настоятельно рекомендуется оставлять включённым, но при желании эту оптимизацию можно выключить.
- **Language Strings** → Определение языковых строк для шаблонов Twig. По умолчанию встроенные термины указывают на языки Grav, поэтому всё совместимо с многоязычностью. При желании можно задать любые конкретные термины. Их также можно полностью настроить на уровне страницы.
  ! Ссылаться на языковую строку из шаблона через глобальную переменную настроек так: <br />`{{ settings.interface.lang.placeholder|t }}`

#### Параметры предпросмотра {: #preview-options }

`![Параметры предпросмотра](frontend-options-2.png?classes=shadow)`

- **Preview Results** → Когда включено, наведение на элемент результатов поиска открывает панель предпросмотра, где можно заглянуть на найденную страницу. Панель предпросмотра включает путь хлебных крошек, заголовок, краткое содержание и список «On This Page».
  ! Использует блок Twig `hits_preview`, на который ссылается [шаблон hits.html.twig](#override-templates)
- **"On This Page" list** → Когда включено и имеет смысл, этот параметр показывает список заголовков, относящихся к выбранному результату. Список отображается в панели предпросмотра, но не показывается, если выбранный элемент — фрагмент заголовка, даже если параметр включён.
  ! Ссылается из [шаблона hits.html.twig](#override-templates)

#### Параметры подвала {: #footer-options }

`![Параметры подвала](frontend-options-3.png?classes=shadow)`

- **Display Footer** → Когда выключено, подвал интерфейса исчезает вместе с пагинацией и копирайтами.
  ! Ссылается из [шаблона footer.html.twig](#override-templates) внутри блока `footer`.
- **Pagination** → Когда включено, позволяет переходить по страницам результатов поиска. Иначе показывается только настроенное число элементов «Hits Per Page».
  ! Использует [виджет `<ais-pagination>`](https://www.algolia.com/doc/api-reference/widgets/pagination/vue/?target=_blank) в [шаблоне pagination.html.twig](#override-templates). Ссылается из [шаблона footer.html.twig](#override-templates).
- **Algolia Copyrights** → Показывает копирайты «Search by Algolia». Помните, что Algolia требует использовать этот виджет, если вы пользуетесь только бесплатными кредитами или находитесь на тарифе Community либо устаревшем Free.
  ! Использует [виджет `<ais-powered-by>`](https://www.algolia.com/doc/api-reference/widgets/powered-by/vue/?target=_blank) в [шаблоне pagination.html.twig](#override-templates). Ссылается из [шаблона footer.html.twig](#override-templates).
- **Powered by Algolia Pro** → Показывает логотип «Powered by Algolia Pro Plugin».
  ! Используется в [шаблоне pagination.html.twig](#override-templates). Ссылается из [шаблона footer.html.twig](#override-templates).

## Использование {: #usage }

Чтобы подключить Algolia Pro на сайте, сначала нужно загрузить шаблон, а затем назначить один или несколько элементов, которые будут открывать интерфейс поиска.

Это очень просто. Давайте посмотрим подробнее.

#### Загрузка шаблона {: #loading-the-template }
Лучшее место для загрузки шаблона — подвал шаблона `base.html.twig`, чтобы он гарантированно загружался на каждой странице.

Всё, что нужно, — одна строка Twig:

```twig
{% include 'partials/algolia-pro/instantsearch.html.twig' ignore missing with { index: 'pages' } %}
```

`Index` — обязательный параметр, и он должен совпадать с настроенным _Index Name_. Он также определяет, какую настройку интерфейса загрузить для поиска.

Когда шаблон загружен на сайте, можно назначать элемент-триггер для взаимодействия с ним.

> [!WARNING] Предупреждение
> На странице можно загрузить только один экземпляр шаблона `instantsearch`.

#### Назначение элемента-триггера {: #delegate-a-trigger-element }
Algolia Pro не поставляется со встроенным элементом интерфейса для поля поиска. По замыслу всё нужное находится внутри модального окна, которое открывается, включая поле поиска.

Всё, что действительно нужно, — открывать интерфейс поиска Algolia Pro через **действие пользователя**. Это может быть **любой** элемент сайта. Поле ввода, кнопка, текстовая ссылка, изображение. Решать вам, и это позволяет по-настоящему бесшовно встроить Algolia Pro.

Поскольку дизайн у каждого сайта разный, мы сделали назначение элемента для открытия поиска предельно простым. Нужно только решить, какой элемент (или элементы) должен срабатывать, и добавить им атрибут `data-algolia-pro-trigger`. Algolia Pro найдёт эти элементы и повесит на них обработчик клика. Теперь каждый раз, когда пользователь нажимает на элемент, Algolia Pro открывается.

##### Пример {: #example }
Предположим, на вашем сайте есть поле **поиска** в правом верхнем углу шапки и кнопка «Search» в боковой панели.

**До**

```html
<!-- поле ввода в шапке -->
<label for="search">Search</label>
<input type="text" name="search" id="search">

<!-- кнопка в боковой панели -->
<button type="button">Search</button>
```

**После**

```html
<!-- поле ввода в шапке -->
<label for="search">Search</label>
<input type="text" name="search" id="search" data-algolia-pro-trigger>

<!-- кнопка в боковой панели -->
<button type="button" data-algolia-pro-trigger>Search</button>
```

### Переопределение шаблонов Twig {: #override-templates }
Интерфейс поиска Algolia Pro — это **приложение Vue**, построенное на **шаблонах Twig**, **блоках Twig** и [виджетах Vue InstantSearch](https://www.algolia.com/doc/api-reference/widgets/vue/?target=_blank). Шаблоны разделены так, чтобы упростить переопределение отдельных частей интерфейса и добавление новых фич.

Даже если вы не знакомы с Vue или JS в целом, вам будет очень просто что-то изменить или расширить, если есть базовые знания системы переопределения шаблонов Grav и Twig.

Прежде чем углубляться в сами шаблоны, стоит сначала представить, как организованы блоки и шаблоны и за какую часть интерфейса они отвечают.

`![Наложение структуры шаблонов](twig-structure-overlay.png?class=overlay-on)`
`![Структура шаблонов](twig-structure.png?class=overlay-on)`

#### instantsearch.html.twig {: #instantsearch-html-twig }
Это **главный** шаблон, тот, который вы [включаете на сайте](#loading-the-template), чтобы загрузить интерфейс.

Здесь [виджет `<ais-instant-search>`](https://www.algolia.com/doc/api-reference/widgets/instantsearch/vue/) инициализируется со всей настройкой и параметрами, которые Algolia Pro определил и сузил для вашей страницы.

В эту страницу включаются ещё несколько шаблонов: [специальный шаблон `assets.html.twig`](#assets-html-twig) и [шаблон `instantsearch-scopes.html.twig`](#instantsearch-scopes-html-twig), оба нужны для стилей и включения остальных шаблонов.

Виджет `<ais-instant-search>` также привязан к собственному приложению Vue, которое поставляется с Algolia Pro: там мы используем собственные middleware и реактивные переменные вроде `isOpen` для отрисовки интерфейса. [Подробнее о приложении Vue, реактивных переменных и программном взаимодействии с Algolia Pro — ниже.](#javascript-and-programmatic-interaction)

Если вы решите переопределить этот шаблон, нужно понимать, что сейчас делает виджет `<ais-instant-search>`, чтобы повторить это в своём шаблоне. Скорее всего, менять здесь что-либо вам никогда не понадобится.

#### instantsearch-scopes.html.twig {: #instantsearch-scopes-html-twig }
Этот шаблон — простой промежуточный контейнер, где импортируются и определяются основные `blocks` Twig. Он намеренно оставлен простым, чтобы легко переопределять его, если понадобится новый блок и Twig.

Обратите внимание, что здесь также загружается второй [специальный шаблон `configure.html.twig`](#configure-html-twig). Если вы переопределяете этот шаблон, учтите, что как минимум нужно включить блок «configure».

#### searchbox.html.twig {: #searchbox-html-twig }
Шаблон searchbox предоставляет блок `searchbox` и служит обёрткой для поля поиска, куда вводятся запросы, и кнопки отмены.

#### searchbox_input.html.twig {: #searchbox-input-html-twig }
Этот шаблон предоставляет блок `searchbox_input` и содержит всю логику показа поля поиска для ввода запросов и запуска результатов.

Этот блок использует [виджет `<ais-search-box>`](https://www.algolia.com/doc/api-reference/widgets/search-box/vue/?target=_blank) и сильно настроен через [**слоты**](https://www.algolia.com/doc/api-reference/widgets/search-box/vue/#customize-the-ui?target=_blank).

Поле ввода в этом блоке запускает каждый запрос и держит состояние приложения Algolia Pro синхронизированным с сервисом Algolia. Переопределяя этот шаблон, учитывайте события и логику слотов, заданные по умолчанию.

#### hits.html.twig {: #hits-html-twig }
Шаблон `hits` предоставляет блок `hits` и служит обёрткой для шаблона результатов поиска ([hits_items](#hits-items-html-twig)) и предпросмотра выбранного результата ([hits_preview](#hits-preview-html-twig)). Этот блок также показывает статистику результатов, если параметр [включён](#user-interface-parameters).

Статистика рисуется через [виджет `<ais-stats>`](https://www.algolia.com/doc/api-reference/widgets/stats/vue/?target=_blank).

#### hits_items.html.twig {: #hits-items-html-twig }
Этот шаблон перебирает все результаты поиска и рисует их. Здесь много логики JavaScript (Vue), но в основном всё сводится к отрисовке элементов определённым образом в зависимости от состояния приложения.

Как и [searchbox_input](#searchbox-input-html-twig), этот шаблон сильно настроен через [слоты](https://www.algolia.com/doc/api-reference/widgets/hits/vue/#customize-the-ui?target=_blank).

Давайте на высоком уровне посмотрим, какая логика JavaScript/Vue в этом шаблоне отвечает за отрисовку результатов.

###### Пустые и непустые результаты {: #empty-vs-non-empty-results }
Первая часть логики проверяет, есть ли вообще результаты для показа. Это можно сделать, проверив, пуст ли слот `items`.

Так приложение может рисовать два совершенно разных вида HTML в зависимости от состояния, что позволяет показать очень упрощённый HTML, когда результатов нет.

```html
<template slot-scope="{ items }">
  <span v-if="!Object.keys(items).length">Empty</span>
  <span v-else>Non Empty</span>
</template>
```

###### Цикл {: #loop }
Когда установлено, что результаты есть, их нужно перебрать и нарисовать по одному.

Мы перебираем их [обычной логикой Vue `v-for`](https://v3.vuejs.org/guide/list.html#v-for-with-an-object?target=_blank) и рисуем каждый элемент как `<li>`. Важно также всегда связывать с каждым элементом уникальный `key`, как рекомендует Vue.

```html
<ul v-if="Object.keys(items).length">
  <li 
    v-for="(item, index) in items" 
    :key="item.objectID"
  >
    <a :href="`{{ uri.rootUrl }}${item.url}`">
      [[ item.title ]]
    </a>
  </li>
</ul>
```

Здесь происходит несколько вещей. Во-первых, можно заметить атрибуты с двоеточием `:`. Это поведение Vue: оно говорит фреймворку вычислить содержимое атрибута. Без двоеточия они были бы просто строками, что нам не нужно.

Во-вторых, для отрисовки заголовка используется синтаксис `[[ item.title ]]`. Обычно Vue оборачивает переменные в фигурные скобки `{{ item.title }}`. Но поскольку Twig и Grav тоже используют фигурные скобки, система шаблонов Algolia Pro настроена на двойные квадратные скобки.

Наконец, обратите внимание на синтаксис значения href. Про двоеточие в атрибуте мы уже знаем. А в значении видна смесь Twig и JavaScript.
Используются шаблонные литералы JavaScript с обратными кавычками (`` ` ``), вычисление URI Twig/Grav `{{ uri.rootUrl }}` и, наконец, вставка значения Vue `item.url` через синтаксический сахар `${item.url}`.

> [!TIP] Совет
> Данные объекта, доступные для каждого элемента, соответствуют полям вашего индекса. Например, `title`, `url`, `summary`, `headers` и другие.

###### Выбранное состояние {: #selected-state }
Приложение Vue Algolia Pro несёт глобальную переменную состояния `selected`, с помощью которой можно по-разному рисовать отдельные части интерфейса. Оно также предоставляет метод `isSelected`, определяющий, выбран ли элемент.

Давайте немного изменим наш `<li>` из **цикла** выше и поменяем поведение элемента при наведении мыши.

```html
<li 
  v-for="(item, index) in items" 
  :key="item.objectID"
  @mouseenter="selected = item"
  :class="{
    'is-selected': isSelected(item)  
  }"
>
```

Теперь элемент слушает наведение мыши ([`@mouseenter`](https://v3.vuejs.org/guide/events.html#listening-to-events?target=_blank)), и когда это происходит, глобальная переменная состояния `selected` получает этот `item`.

Кроме того, если на элемент действительно навели мышь, ему добавляется класс `is-selected` благодаря тому, что `isSelected(item)` возвращает true. Если элемент не выбран, метод `isSelected` возвращает false, и имя класса не добавляется.

###### Подсветка результатов {: #highlighting-results }
Можно подсветить часть текста по запросу. Например, если искать «**colle**», мы ожидаем, что результаты со словом «Collection» будут подсвечены как «**`Colle`ction**».

Это очень просто сделать с помощью [виджета `<ais-highlight>`](https://www.algolia.com/doc/api-reference/widgets/highlight/vue/?target=_blank). Передав виджету объект `item` и свойство, которое нужно подсветить, вы получите корректно подсвеченный HTML-элемент.

Давайте возьмём элемент из предыдущих разделов и вместо простой отрисовки текста `[[ item.title ]]` сделаем так, чтобы он подсвечивался при необходимости.

```html
<ul v-if="Object.keys(items).length">
  <li 
    v-for="(item, index) in items" 
    :key="item.objectID"
    @mouseenter="selected = item"
    :class="{
      'is-selected': isSelected(item)  
    }"
  >
    <a :href="`{{ uri.rootUrl }}${item.url}`">
      <ais-highlight
        attribute="title"
        :hit="item"
        highlighted-tag-name="span"
        :class-names="{
          'ais-Highlight-highlighted': 'bg-yellow text-black'
        }"
      ></ais-highlight>
    </a>
  </li>
</ul>
```

Теперь элементы рисуют заголовок внутри тегов `span` и правильно подсвечивают части текста при совпадении с запросом, добавляя классы `bg-yellow text-black`.

###### Заключение {: #conclusion }
Синтаксис и логика, объяснённые выше, используются во всём интерфейсе; их понимание очень пригодится, если вы решите расширить и создать собственный интерфейс. Структура и гибкость шаблонов и приложения позволят вам использовать разные подходы, если следовать стандартам JavaScript и Vue.

#### hits_preview.html.twig {: #hits-preview-html-twig }
Шаблон `hits_preview` предоставляет блок Twig, который показывает панель предпросмотра с подробностями выбранного элемента результатов поиска.

Как мы узнали в разделе [Выбранное состояние](#selected-state), `selected` — глобальная переменная состояния, доступная нам во всех шаблонах интерфейса, чтобы определять, выбран ли элемент.
Панель предпросмотра пользуется этим, оборачивая весь контейнер в условие, которое это проверяет.

```html
<div v-if="selected">[... preview panel HTML ...]</div>
```

В отличие от раздела [цикла `hits_items`](#loop), панели предпросмотра не нужно перебирать элементы. Вместо этого можно показать подробности об элементе, ссылаясь на объект `selected`.

Если вы хотите показать заголовок и краткое содержание выбранного элемента, сделайте так:

```html
<div v-if="selected">
  <h1>[[ selected.title ]]</h1>
  <p>[[ selected.summary ]]</p>
</div>
```

> [!TIP] Совет
> Вы можете подсветить текст объекта `selected` при совпадении с запросом, используя виджет `<ais-highlight>`. [Подробнее](#highlighting-results)

> [!NOTE] Примечание
> В этом блоке также находится логика раздела «On This Page».

#### footer.html.twig {: #footer-html-twig }
Подвал — нижняя область интерфейса, и его можно полностью отключить [в настройках «Footer Options»](#user-interface-parameters).

Помимо простого HTML и логики Twig для показа и скрытия элементов подвала, шаблон также включает блок `pagination`. Он вынесен в отдельный шаблон, чтобы лучше разделить логику html/twig и виджет Vue.

#### pagination.html.twig {: #pagination-html-twig }
Этот блок — отрисовка [виджета `<ais-pagination>`](https://www.algolia.com/doc/api-reference/widgets/pagination/vue/?target=_blank), и он полностью настроен через [слоты](https://www.algolia.com/doc/api-reference/widgets/pagination/vue/#customize-the-ui?target=_blank).

### Специальные шаблоны {: #special-templates }
Есть пара специальных шаблонов, созданных, чтобы отделить часть логики от интерфейса и упростить расширение и изменение интерфейса, не затрагивая всё остальное напрямую.

#### assets.html.twig {: #assets-html-twig }
Шаблон assets отвечает за загрузку CSS и JavaScript, которые заставляют интерфейс работать. Без них на фронтенде вряд ли что-то будет работать и выглядеть как надо.

Шаблон содержит логику загрузки встроенных стилей, которые при необходимости можно [отключить](#user-interface-parameters), и добавляет на сайт динамическую CSS-переменную для акцентного цвета.

Там же есть логика загрузки JavaScript из скомпилированной версии (обычно этого достаточно) или через Webpack HMR, если вы решите с ним разрабатывать.

###### Tailwind CSS {: #tailwind-css }
Интерфейс Algolia Pro построен на популярном CSS-фреймворке [TailwindCSS](https://tailwindcss.com/?target=_blank). Если на вашем сайте уже есть Tailwind CSS, стоит отключить встроенный CSS в [настройках](#user-interface-parameters).

Кроме того, нужно перекомпилировать CSS вашей темы. Для этого убедитесь, что папка плагина `algolia-pro` входит в источники содержимого в `tailwind.config.js` вашей темы.

```js
// Tailwind 2
purge: {
  content: [
    // ...
    '../../plugins/algolia-pro/**/*.twig',
  ]
}

// Tailwind 3
content: [
  // ...
  '../../plugins/algolia-pro/**/*.twig',
]
```

> [!NOTE] Примечание
> Возможно, придётся поправить родительские пути `..` в зависимости от расположения `tailwind.config.js` относительно папки `user`.

#### configure.html.twig {: #configure-html-twig }
Шаблон `configure` служит посредником между настройками Algolia Pro и сервисом Algolia InstantSearch. Это происходит в блоке `configure` и через [виджет `<ais-configure>`](https://www.algolia.com/doc/api-reference/widgets/configure/vue/?target=_blank).

Предоставленная реализация перебирает все настройки в конфигурации **Search Parameters** (`settings.search`) и передаёт их в `<ais-configure>`. Если вы не уверены в том, что делаете, менять этот шаблон не рекомендуем.

> [!NOTE] Примечание
> Атрибуты, разделённые дефисами, нужно преобразовывать модификатором `.camel`. Например, `hits-per-page` должен рендериться как `hits-per-page.camel`.

## JavaScript и программное взаимодействие {: #javascript-and-programmatic-interaction }
Как разработчику вам может пригодиться возможность взаимодействовать с классом фронтенда Algolia Pro. Algolia Pro позволяет это, открывая глобальный массив экземпляров `AlgoliaPro` в `window`.

Глобальный объект не открыт по умолчанию и может вернуть строку `protected` вместо ожидаемого объекта. Если он нужен из вашего JavaScript, включите параметр [Expose Global JS Object](#user-interface-parameters).

Как и любую другую настройку интерфейса, можно выбрать, какой экземпляр открывать, а какой нет. Однако сейчас мы поддерживаем только один экземпляр за раз.

Обращаясь к объекту, используйте индекс `0` массива. Сейчас Algolia Pro предоставляет и тестирует только один экземпляр. Ниже список свойств и методов, доступных из глобального объекта `window.AlgoliaPro[0]`:

##### Свойства {: #properties }
Некоторые свойства реактивны: вы можете менять их значения и влиять на состояние приложения. Например, чтобы открыть модальное окно программно, напишите `window.AlgoliaPro[0].isOpen = true`.

- **isOpen** → (_реактивное_) Состояние модального окна Algolia Pro, открыто оно или нет. Задайте `true` или `false`, чтобы открыть или закрыть.
- **warmConnection** → Текущая настройка тёплого соединения. [См. настройку](#user-interface-parameters).
- **selected** → (_реактивное_) Текущий выбранный элемент. Содержит объект Algolia со всеми подробностями элемента. Задайте `null`, чтобы снять выбор.
- **query** → Текущий запрос поиска.
- **appearance** → Текущий параметр оформления. [См. настройку](#user-interface-parameters).
- **activeAppearance** → Текущая фактически активная тема с автоматическим вычислением, если задана система. Может быть `light` или `dark`.
- **isDark** → Тёмная ли тема оформления.
- **mq** → Объект [Media Query List](https://developer.mozilla.org/en-US/docs/Web/API/Window/matchMedia?target=_blank), на котором висит событие `change` системной цветовой схемы.
- **searchClient** → Экземпляр поискового клиента Algolia. Это основной объект InstantSearch, который делает всю магию. [Документация](https://www.algolia.com/doc/api-reference/widgets/instantsearch/js/#widget-param-searchclient?target=_blank)

##### Методы {: #methods }
- **isSelected(item)** → Проверяет, выбран ли переданный объект элемента.
- **setAppearance(appearance)** → Меняет тему оформления поиска. Может быть `light`, `dark` или `system`.
