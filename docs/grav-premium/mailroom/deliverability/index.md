# Доставляемость {: #deliverability }

Попадёт ли ваша почта во входящие, зависит от DNS вашего домена, того, как сайт передаёт почту, и поведения вашего списка. Экран **Health** Mailroom проверяет все три и говорит, что делать с тем, что не проходит. Эта страница описывает проверки, предупреждения и список исключений, который защищает вашу репутацию отправителя.

## Экран Health {: #the-health-screen }

Откройте **Health** в Mailroom. Экран говорит «N of N checks pass» и перечисляет каждую проверку в трёх группах, с состоянием (**Pass**, **Worth a look**, **Failing** или **Not yet**), предложением о том, что верно, и в **What to do** — предложением о том, как это исправить.

| Группа | Проверка | На что смотрит |
|---|---|---|
| Your domain | SPF | Одна запись SPF на вашем отправляющем домене, что она разрешает вашему транспорту отправлять за вас, что она остаётся в пределах десяти запросов и не заканчивается на `+all`. |
| | DKIM | Ключ подписи в `{selector}._domainkey.{domain}` и что он указывает туда, где ваш текущий транспорт хранит ключи. |
| | DMARC | Запись DMARC с политикой (Gmail и Yahoo требуют её от массовых отправителей с февраля 2024 года). `p=none` стоит посмотреть. |
| | From address | Что он есть, что это адрес, что он не от бесплатного почтового провайдера и что он на домене, о котором говорят проверки выше. |
| Your transport | Plain-text part | Кампании уходят с текстовой частью, а также с HTML. |
| | One-click unsubscribe | Заголовки отписки переживают ваш транспорт, поэтому Gmail показывает свою кнопку Unsubscribe. |
| | Sending rate | **Messages Per Minute** не равен нулю и не больше того, что справляются обработчик и большинство тарифов провайдеров. |
| | Bounce webhook | Webhook провайдера настроен, и от него недавно были события. |
| | The queue worker | Обработчик запускался за последние 15 минут, пока ждут задания. |
| | Site URL | Mailroom знает адрес, с которого начинаются ссылки в письмах. |
| Your list | Bounces and complaints | Ваши проценты возвратов и жалоб за последние тридцать дней против границ, публикуемых получателями. |

Проверки списка заполняются после первой кампании; проверки домена работают сразу. Ответы кэшируются на десять минут: после изменения записи DNS нажмите **Check again**.

### Когда проверка не может определить {: #when-a-check-cannot-work-it-out }

Домен берётся из вашего адреса From, а селектор DKIM — из вашего транспорта, что работает почти для любого сайта. Вкладка **Health** в настройках Mailroom покрывает остальное:

| Настройка | Название | Когда задавать |
|---|---|---|
| `deliverability.sending_domain` | Sending Domain | Ваши записи DNS живут на домене, отличном от того, что в адресе From, например при отправке как `hello@example.com` через делегированный `mail.example.com`. |
| `deliverability.dkim_selector` | DKIM Selector | Часть перед `._domainkey` в записи DKIM, которую дал провайдер, когда транспортный плагин не может запросить её через API провайдера. Два селектора во время ротации допустимы, через запятую. |
| `deliverability.return_path` | Custom Return Path | Хост, который провайдер велел вам направить CNAME в их зону return-path, например `em1234.example.com`, когда проверка SPF продолжает падать на домене, который, как вы знаете, настроен. |

### Предупреждения {: #alerts }

Две вещи поднимают баннер на панели управления Admin Next:

- непрошедшая проверка: «Mail from this site may not be landing: ... is failing», с **Open Health**;
- процент возвратов выше **Bounce Rate That Raises an Alert** (`alerts.bounce_rate_percent`, 5, на вкладке **Health**) за последние тридцать дней. Здоровый список никогда не видит пяти процентов; устаревший импортированный список видит их в первой кампании, пока это ещё можно исправить.

### В командной строке {: #on-the-command-line }

```bash
bin/plugin mailroom deliverability:check            # проверить всё сейчас
bin/plugin mailroom deliverability:check --cached   # использовать десятиминутный кэш
bin/plugin mailroom deliverability:check --strict   # завершаться ошибкой и при предупреждении
```

Она печатает те же три группы с теми же предложениями и выходит с `1`, когда какая-либо проверка не проходит (или, с `--strict`, когда какая-либо стоит внимания), поэтому подходит рядом со `status` во всём, что запускается после развёртывания.

## Возвраты и жалобы {: #bounces-and-complaints }

Когда настроен [webhook провайдера](../sending-and-providers/index.md#provider-webhooks):

- **жёсткий возврат** (почтового ящика не существует) исключает адрес и убирает человека из всех списков;
- **мягкие возвраты** (переполненный ящик, временный отказ) считаются, и три за тридцать дней считаются одним жёстким;
- **отклонённое** сообщение (провайдер вообще не стал его отправлять, например из-за квоты) отмечает отправку возвратом и ничего не говорит о человеке;
- **жалоба** (кнопка спама) исключает адрес и убирает человека из всех списков.

Без webhook возвраты никогда не записываются, и на эти адреса пишут снова в следующий раз. Проверка **Bounces and complaints** говорит об этом, когда возвраты считаются, а ничего не исключено.

## Исключения {: #suppressions }

Вкладка **Suppressions** перечисляет адреса, на которые этот сайт больше никогда не напишет, что бы ни говорили список или импорт, с причиной и временем:

| Причина | Как попал |
|---|---|
| Bounced | Жёсткий возврат или три мягких за тридцать дней |
| Complaint | Кнопка спама |
| Added by hand | **Add an address** или строка `unsubscribed` в импорте |
| Not a valid address | Добавлен вручную как неверный |

- **Add an address** — для того, кто попросил вас напрямую, а не по ссылке. Добавьте **Note** с причиной для того, кто прочитает её через год.
- **Remove** спрашивает «Start mailing this address again?». Делайте это, только когда знаете, почему адрес там оказался: отправка на адрес, который жаловался, — так теряют репутацию отправителя. Снятие исключения никого не подписывает заново.
- Строка **address erased** принадлежала тому, кто попросил забыть его. Хранится только хеш адреса, поэтому на него всё равно никогда не пишут.

Аудитория каждой кампании проверяется по списку до того, как написано хоть одно сообщение, и снова при сборке каждого сообщения. Исключения хранятся по хешу SHA-256 адреса, поэтому они переживают удаление данных.
