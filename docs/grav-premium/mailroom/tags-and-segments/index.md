# Теги и сегменты {: #tags-and-segments }

Список — тема, которую человек выбрал. Тег — то, что заметил сайт. Сегмент — вопрос, заданный и тому, и другому. Теги и сегменты живут на вкладке **Audience**, под списками.

## Теги {: #tags }

Тег — метка на человеке, например `webinar` или `early-adopter`. У него нет согласия и состояния: снятие тега никого не отписывает, а удаление тега снимает его со всех, у кого он есть, и больше ничего не меняет.

Теги появляются из:

- параметра `tags` блока подписки, параметра `tags` действия плагина Form или `tags` в [API подписки](../subscribe-api/index.md);
- столбца **Tags** импорта или **Tag everybody in this file**;
- страницы человека (чипы и поле «A tag, new or existing») или **Add tag** на [панели массовых действий](../bulk-actions/index.md);
- шага **Add a tag** автоматизации.

**Add a tag** на вкладке Audience создаёт тег из **Label**. Коды нормализуются: строчные буквы, пробелы и подчёркивания превращаются в дефисы, поэтому «Early Access», «early access» и «early-access» — один тег. Каждый тег показывает, сколько людей его несут, а счётчик открывает таблицу Subscribers, отфильтрованную по ним.

Тег может запускать автоматизацию: **When the tag ... is added** (см. [Автоматизации](../automations/index.md)).

## Сегменты {: #segments }

Сегмент — сохранённый вопрос об аудитории: кто в каком списке, кто перестал открывать, кто присоединился в прошлом месяце. На его ответ можно нацелить кампанию или автоматизацию.

### Создание {: #build-one }

На вкладке **Audience** нажмите **Build a segment**:

1. Дайте ему **Name** (по нему вы его выбираете, когда пишете кампанию) и необязательное **Description**.
2. **Limit it to a list** или оставьте на **Everybody subscribed** и позвольте кампании решить список.
3. Добавьте условия в **All of these** (человек должен совпасть с каждым), **Any of these** (хотя бы с одним) и **None of these** (любой совпавший с одним исключается). Каждое условие — это **Field**, **Operator** и **Value**.
4. Смотрите **Who matches** рядом с редактором: счётчик по мере построения и первые десять человек. Условия, где ещё ничего не заполнено, не участвуют в счётчике.
5. Сохраните.

Любой исключённый, уже отсутствующий в списке или никогда не подтвердивший подписку исключается из каждой аудитории, что бы ни говорили условия, и счётчик говорит, сколько («12 are left out.»).

### Поля и операторы {: #fields-and-operators }

| Поле | Операторы | Значение |
|---|---|---|
| On list | is, is not | Список |
| Tagged | is, is not | Тег |
| Subscriber status | is, is not | Состояние |
| Joined | is before, is after, is within the last, is longer ago than | Дата или число дней |
| How they joined | is, is not | `form`, `import`, `api`, `admin` или `automation` |
| Language | is, contains, is set, is empty | Код языка |
| Was sent campaign | is, is not | Кампания |
| Opened campaign | is, is not | Кампания |
| Clicked in campaign | is, is not | Кампания |
| Has not opened anything in | is at least | Число дней |

Редактор группирует их в **Subscriber** и **Engagement**.

### Счётчики {: #counts }

Счётчик сегмента вычисляет обработчик, а не каждое открытие страницы, поэтому каждый экран говорит, насколько он старый («Counted 4 minutes ago»). Обработчик пересчитывает устаревшие сегменты каждые **Recount Segments Every** (`segments.count_every_minutes`, 15, на вкладке **Segments**); `0` пересчитывает при каждом запуске обработчика, что полезно, пока вы строите сегмент, но не то, что стоит оставлять включённым. Изменение условий или списка сегмента очищает его счётчик до следующего пересчёта. Редактор сегмента считает по мере построения, поэтому после того, как люди подписались, ушли или получили тег, он может показывать число, отличное от списка; тогда он говорит, что список показывает счётчик с последнего пересчёта, а **Recount** сводит их вместе.

В строке каждого сегмента есть **Recount** (сейчас), **Duplicate** и **Delete**, и она говорит, сколько кампаний его используют. Сегмент, на который указывают черновики или запланированные кампании, нельзя удалить, пока они не укажут в другое место. Сегмент, который не удаётся посчитать (обычно поле из чего-то уже не установленного), поднимает баннер на панели управления «The segment ... could not be counted».

Из командной строки:

```bash
bin/plugin mailroom segments:count          # пересчитать все сегменты сейчас
bin/plugin mailroom segments:count --id=4   # один сегмент
bin/plugin mailroom segments:preview 4      # число, кто исключён, и десять замаскированных адресов
```

### Где используются сегменты {: #where-segments-are-used }

- **Кампании**: **Narrow it with a segment** отправляет только людям в списках кампании, которые также совпадают с ним, а **All lists, with a segment** отправляет всем в любом списке, кто совпадает (см. [Кампании](../campaigns/index.md#who-it-goes-to)). Сегменту, ограниченному списком, нужен этот список среди списков кампании.
- **Автоматизации**: **Only people matching this segment** решает, кого включить (см. [Автоматизации](../automations/index.md)).

### В API {: #in-the-api }

Условия сегмента — документ с тремя контейнерами, `all`, `any` и `none`, каждый из которых является списком `{field, op, value}`:

```json
{
  "name": "Quiet readers",
  "list_id": 1,
  "definition": {
    "all": [
      {"field": "not_opened_in_days", "op": "gte", "value": 90},
      {"field": "subscribed_at", "op": "older_than_days", "value": 180}
    ],
    "none": [
      {"field": "tag", "op": "is", "value": 7}
    ]
  }
}
```

`GET /mailroom/segments/vocabulary` перечисляет каждое поле с его типом, операторами и параметрами; `POST /mailroom/segments/preview` отвечает на документ, не сохраняя его. См. [REST API](../rest-api/index.md#segments).
