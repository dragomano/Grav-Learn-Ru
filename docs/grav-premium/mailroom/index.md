# Mailroom {: #mailroom }

**Mailroom** — рассылка новостей, которая работает внутри вашего сайта на Grav. Люди подписываются через блок на ваших страницах, подтверждают подписку по почте и попадают в выбранные списки. Вы пишете кампании в Admin Next, отправляете их через плагин Email для Grav и читаете результаты на экранах, которые считают открытия и переходы в вашей собственной базе данных. Всё хранится в базе, которой управляете вы: SQLite по умолчанию, MySQL или PostgreSQL.

Цифры принадлежат вам. Открытие или переход — это отметка времени рядом со строкой отправки, без IP-адреса, браузера и местоположения, и история остаётся, когда вы меняете компанию, которая доставляет вашу почту.

> [!IMPORTANT] Важно
> Продуктам Premium нужен бесплатный плагин [License Manager](https://getgrav.org/premium/license-manager). Установите его и добавьте лицензию продукта перед установкой Mailroom.

## Требования {: #requirements }

| Требование | Примечания |
|---|---|
| **Grav** `>= 2.1.0` | Mailroom несовместим с Grav 1.7 |
| **PHP** `>= 8.3` | С PDO и драйвером вашей базы данных: `pdo_sqlite`, `pdo_mysql` или `pdo_pgsql` |
| **Плагин API** `>= 1.0.31` | Обеспечивает экраны админки и REST API |
| **Плагин Email** `>= 5.1.0` | Вся исходящая почта. Он должен быть настроен и отправлять письма |
| **Admin Next** | Где вы работаете. Администраторам нужен `api.access` |
| **База данных** | SQLite (создаётся для вас, по умолчанию), MySQL или MariaDB, либо PostgreSQL |

Необязательные плагины добавляют больше возможностей:

| Плагин | Что добавляет |
|---|---|
| `form` | Действие `mailroom` плагина Form для формы подписки, которую вы определяете сами |
| Транспортный плагин, например `email-smtp2go`, `email-amazon`, `email-sendgrid`, `email-postmark`, `email-mailgun`, `email-mailersend` или `email-resend` | Отчёты о доставке, возвратах и жалобах через webhook провайдера, а также проверку доставляемости, которая знает вашего провайдера |

Mailroom работает и без них. Без webhook провайдера кампании всё равно отправляются; цифры доставленных, возвратов и жалоб остаются пустыми.

## Что входит {: #what-s-in-the-box }

- **Подписчики с записью согласия**: предложение, с которым человек согласился, когда и с какого адреса, а также история согласий по каждому изменению его списков.
- **Списки, из которых можно выйти по отдельности**, каждый со своим двойным подтверждением подписки, центром предпочтений и отпиской одним щелчком из почтового клиента.
- **Блок подписки где угодно**: `{{ mailroom_form() }}` в теме или на странице, действие `mailroom` плагина Form или JSON-эндпоинт, на который может отправлять другой сервер.
- **Кампании** в Markdown — в один список, несколько списков или во все списки с сегментом, с тестами темы письма, тестовыми отправками, планированием, отправкой тем, кто присоединился позже, и повторной попыткой для неудачных отправок.
- **Сегменты**, построенные из условий, **теги**, **шаблоны** и **автоматизации**, которые запускаются при подписке, подтверждении или появлении тега.
- **Импорт и экспорт CSV** с сопоставлением столбцов, пробным запуском и правилами, которые не дают ушедшим вернуться.
- **Проверки доставляемости** для SPF, DKIM, DMARC, адреса From, заголовков отписки, скорости отправки, webhook возвратов и ваших процентов возвратов и жалоб.
- **Семь отчётов** — от эффективности кампаний до часа, в который читают ваши читатели.
- **Инструменты конфиденциальности**: данные одного человека в виде JSON-файла и удаление по адресу, после которого остаётся только хеш исключения.
- **REST API и инструменты MCP** для всего, что делает админка.
