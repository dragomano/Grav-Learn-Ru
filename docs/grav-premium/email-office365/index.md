# Email Office365

> [!IMPORTANT] Важно
> Для премиальных продуктов требуется бесплатный плагин [License Manager](../license-manager/index.md). Установите его и добавьте лицензию продукта перед установкой этого продукта.

## Установка

Установить плагин Email Office365 можно одним из трёх способов: способ через GPM (менеджер пакетов Grav) позволяет быстро установить плагин одной командой в терминале, ручной способ — через zip-архив, а способ через админку — с помощью плагина Admin.

### Установка через GPM (предпочтительно)

Чтобы установить плагин через [GPM](http://learn.getgrav.org/advanced/grav-gpm), откройте терминал системы (его также называют командной строкой), перейдите в корень установки Grav и введите:

```
bin/gpm install email-office365
```

Плагин Email Office365 будет установлен в папку `/user/plugins` внутри Grav. Его файлы находятся в `/your/site/grav/user/plugins/email-office365`.

### Установка вручную

Чтобы установить плагин вручную, скачайте zip-версию этого репозитория и распакуйте её в `/your/site/grav/user/plugins`. Затем переименуйте папку в `email-office365`. Эти файлы можно найти на [GitHub](https://github.com/yourname/grav-plugin-email-office365).

Теперь все файлы плагина должны находиться в

```
/your/site/grav/user/plugins/email-office365
```

### Установка через плагин Admin

Если вы используете плагин Admin, плагин можно установить напрямую: откройте меню `Plugins` и нажмите кнопку `Add`.

## Конфигурация

Перед настройкой плагина скопируйте `user/plugins/email-office365/email-office365.yaml` в `user/config/plugins/email-office365.yaml` и редактируйте только эту копию.

Ниже приведена конфигурация по умолчанию и пояснения к доступным параметрам:

```yaml
enabled: true
client_id: ''
client_secret: ''
tenant_id: ''
test_email: ''
```

Учтите: если вы используете плагин Admin, после сохранения конфигурации в админке файл с вашей конфигурацией `email-office365.yaml` будет сохранён в папке `user/config/plugins/`.

## Настройка приложения Azure AD

Перед использованием плагина нужно зарегистрировать приложение на портале Azure. Краткое руководство:

1. Войдите на [портал Azure](https://portal.azure.com/)
2. Найдите и выберите «Azure Active Directory»
3. В разделе «Manage» выберите «App registrations» > «New registration»
4. Укажите имя приложения
5. В поле «Supported account types» выберите «Accounts in this organizational directory only»
6. Для Redirect URI установите тип «Web» и укажите URL обратного вызова (например, `https://my-site.example/office365oauth/callback`)
7. Нажмите «Register»
8. Запишите «Application (client) ID» и «Directory (tenant) ID» со страницы обзора
9. В разделе «Manage» выберите «Certificates & secrets»
10. Нажмите «New client secret», укажите описание, выберите срок действия и нажмите «Add»
11. Сразу скопируйте значение секрета (увидеть его снова не получится)
12. В разделе «Manage» выберите «API permissions»
13. Нажмите «Add a permission» > «Microsoft Graph» > «Delegated permissions»
14. Найдите и выберите разрешения `Mail.Send`, `User.Read` и `offline_access`
15. Нажмите «Add permissions»
16. Нажмите «Grant admin consent for [your organization]»

## Использование

После установки и настройки плагина с учётными данными приложения Azure AD:

1. Перейдите в админку Grav > Plugins > Email Office365
2. Настройте плагин, указав учётные данные приложения Azure AD
3. Нажмите кнопку «Authorize», чтобы получить токен обновления (вы будете перенаправлены в Microsoft для предоставления разрешения)
4. После авторизации вы вернётесь на свой сайт Grav, а токен обновления сохранится автоматически
5. Настройте плагин Email, чтобы использовать `Office365` как движок отправки почты
6. Проверьте настройку, отправив тестовое письмо

## Настройка плагина Email

Нужно настроить плагин Email на использование почтового движка Office365:

```yaml
mailer:
  engine: office365
```

## Решение проблем

Если возникают проблемы с отправкой писем:

1. Проверьте, что токен обновления сохранён правильно
2. Убедитесь, что у приложения Azure AD есть нужные разрешения
3. Убедитесь, что redirect URI точно совпадает с указанным в Azure
4. Попробуйте заново сгенерировать токен обновления, снова нажав кнопку «Authorize»
5. Проверьте журналы Grav, чтобы увидеть подробные сообщения об ошибках
