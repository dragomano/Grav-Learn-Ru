# SEO Magic

> [!IMPORTANT] Важно
> Продукты Premium требуют бесплатного плагина [License Manager](../license-manager/index.md). Установите его и добавьте лицензию продукта, прежде чем устанавливать этот продукт.

## Установка

Сначала убедитесь, что у вас установлена последняя версия **Grav 1.7** (`-f` принудительно обновляет индекс GPM).

```
$ bin/gpm selfupgrade -f
```

Для правильной работы плагин SEO Magic использует плагин **sitemap**. Оба доступны через GPM, а поскольку у плагина есть зависимости, достаточно продолжить установку плагина SEO Magic и подтвердить установку остальных, когда появится запрос:

```
$ bin/gpm install seo-magic
```

Установить тему также можно через раздел **Плагины** в плагине Admin.

## Конфигурация

У **SEO Magic** много параметров конфигурации, которые помогают управлять работой плагина. Их можно разбить на разделы, и мы рассмотрим их по очереди.

### Общая конфигурация

`![Общая конфигурация](general-config.png?class=image-shadow)`

* **Статус плагина** → Включает или отключает весь плагин. Когда плагин отключён, значок на панели не отображается, вкладка SEO Magic не показывается при редактировании страниц и т. д.

* **Действия SEO Magic** → Вы можете легко **перегенерировать** данные SEO на основе карты сайта или очистить и **удалить** существующие данные.

* **Включить иконку быстрой панели** → Иконка быстрой панели выглядит как волшебная палочка и позволяет быстро **перегенерировать** данные SEO из любого места админки.

* **Включить события страниц в админке** → По умолчанию, когда эта фича включена, **сохранение** страницы вызывает перегенерацию данных SEO для этой страницы. **Удаление** страницы вызывает удаление данных SEO.

* **Включить отчёт SEO для страницы** → Отчёт SEO — это подвкладка, доступная на вкладке **SEO Magic** при редактировании содержимого страницы. Отчёт анализирует существующие данные SEO и предоставляет отчёт, который помогает улучшить позиции текущей страницы в поиске.

* **Включить отчёт SEO по всему сайту** → Если эта фича включена, полный отчёт по сайту доступен в разделе **Инструменты** → **Отчёты** админки.

* **Строка User Agent** → User-agent, который использует сборщик данных SEO Magic. Вы можете настроить таргетинг на это имя агента и игнорировать эти страницы обхода в данных аналитики.

* **Тайм-аут клиента** → Теперь можно настроить время, по истечении которого HTTP-клиент, используемый для обхода страниц, изображений и ссылок, завершает работу по тайм-ауту. Это значение — количество секунд до тайм-аута. Чем меньше число, тем быстрее процесс, но тем выше вероятность тайм-аутов и потенциально _ложноотрицательных_ результатов.

* **Подключения клиента** → Количество одновременных подключений, которые может использовать HTTPClient

* **Строка Robots** → если в корне вашего сайта нет файла `robots.txt`, SEO Magic использует эту строку и динамически задаст её в метатеге для каждой страницы. [Подробнее о метатеге `robots`](https://moz.com/learn/seo/robots-meta-directives?target=_blank)

* **CSS-селекторы тела** → Массив CSS-селекторов, которые SEO Magic использует для поиска контента, разбираемого и применяемого для автоматического определения **мета-описания** и **мета-ключевых слов**.

* **Свои стоп-слова** → Слова, которые следует игнорировать: они не выбираются из контента и не используются как ключевые слова. Они не считаются _интересными_ словами.

### Конфигурация проверки ссылок

`![Проверка ссылок](link-checker.png?class=image-shadow)`

* **Включить проверку ссылок** → Новая фича, которая проверяет все ссылки на каждой странице, доступна как часть процесса **генерации данных SEO**. Когда она включена, состояние ссылок отображается в отчётах по странице и по сайту.

* **Тайм-аут проверки ссылок** → Сколько ждать до тайм-аута при обходе изображений и ссылок

* **Максимум повторов** → Сколько раз повторять попытку для битой или недоступной ссылки

* **URL в белом списке** → Игнорировать ссылки на эти URL

### Конфигурация мета-контента

`![Конфигурация метаданных](meta-content.png?class=image-shadow)`

* **Включить OpenGraph** → Автоматически рендерить метатеги OpenGraph при отображении страницы.

* **Включить Twitter Card** → Автоматически рендерить метатеги, специфичные для Twitter, при отображении страницы.

* **Имя пользователя Twitter** → Ваше имя пользователя, добавляющее контекст для карточки Twitter.

* **Тип карточки Twitter** → Стиль карточки Twitter для отображения. Варианты: `Summary Large Image`, `Summary`, `App` и `Player`.

* **Включить Facebook Card** → Автоматически рендерить метатеги, специфичные для Facebook, при отображении страницы.

* **Приложение Facebook** → ID приложения Facebook, связанного с этим сайтом. Это может быть полезно для отслеживания, и Facebook рекомендует его указывать. Найти его можно на [панели разработчика Facebook](https://developers.facebook.com/apps/redirect/dashboard?target=_blank).

### Конфигурация мета-изображений {: #meta-images-configuration }

`![](meta-images.png?class=image-shadow)`

* **Тип изображения** → Выберите один из следующих подходов к поиску изображения для использования в метаданных и тегах OpenGraph:

    | Вариант | Описание |
    |--------|-------------|
    |**Автоматически** | SEO Magic перебирает следующий список типов изображений, пока не найдёт изображение: `Image Name` → `Image Attribute` → `OG-Image` → `First image found in Page` → `Default URL`|
    |**WebShot: автоматический сервис скриншотов** | **Эксклюзив SEO Magic!** Каждая лицензия SEO Magic даёт право зарегистрировать URL, который затем можно использовать для автоматического создания скриншотов ваших страниц. Они генерируются и кэшируются для оптимальной производительности |
    |**Определённое имя файла в папке каждой страницы** | Выбранное ниже `Image Name` будет использовано (если существует) как скриншот для страницы. |
    |**Определённый атрибут в заголовках страницы** | Имя файла изображения, указанное в `Image Attribute` в заголовках страницы (метаданных страницы), будет использовано (если существует) как скриншот для страницы.|
    |**Готовый OG-Image на странице** | Вариант `OG-Image` использует существующий `og-image.jpg` или `og-image.png`, найденный в папке страницы. |
    |**Первое изображение, найденное на странице** | Просто берётся первое изображение, найденное на странице. Обычно это первое изображение **по алфавиту**, но порядок может зависеть от вашей файловой системы. |
    |**URL конкретного изображения по умолчанию** | Для всех изображений будет использоваться конкретный URL изображения |

> [!IMPORTANT] Важно
> Порядок резервного выбора изображений по умолчанию совпадает с режимом **Автоматически**. Все остальные режимы также переходят от выбранного варианта к следующему справа. Например, если вы выбрали для типа изображения **OG-Image**, SEO Magic сначала будет искать подходящие файлы OG-Image; если их нет, он попробует использовать **Первое изображение, найденное на странице**; если изображение вообще не найдено, он попробует использовать указанное **Изображение по умолчанию**.

* **Имя изображения** → Имя изображения по умолчанию, которое следует использовать, если оно найдено на конкретной странице.

* **Атрибут изображения** → Атрибут изображения, который, если он задан, содержит имя файла изображения, используемого как изображение страницы.

* **Изображение по умолчанию** → URL изображения, которое будет использоваться, если другое изображение найти не удалось.

* **Размер изображения X** → Ширина генерируемого изображения в `px`.

* **Размер изображения Y** → Высота генерируемого изображения в `px`.

### Конфигурация автогенерации метаданных {: #meta-auto-generation-configuration }

`![Автогенерация метаданных](meta-auto-generation.png?class=image-shadow)`

* **Сохранять символы UTF8** → Включено по умолчанию для поддержки символов UTF-8 в многоязычном контенте. Отключите, если у вас возникают проблемы со странными символами UTF-8 в автоматически сгенерированном контенте.

* **Глобальные ключевые слова** → Массив ключевых слов, которые будут добавлены в начало любых автоматически сгенерированных ключевых слов. Это особенно полезно, если у вас есть ключевые слова, подходящие для всех страниц.

* **Глобальные ключевые слова** → Включает или отключает возможность автогенерации ключевых слов. Ключевые слова основаны на контенте, найденном с помощью `CSS Body Selectors` в разделе **Общая конфигурация** выше.

* **Резервные ключевые слова по умолчанию** — Включает или отключает возможность использовать резервные значения ключевых слов, указанные в **Конфигурации сайта**, если они доступны.

* **Глобальное описание** → Включает или отключает возможность автогенерации описания. Описание основано на контенте, найденном с помощью `CSS Body Selectors` в разделе **Общая конфигурация** выше.

* **Резервное описание по умолчанию** — Включает или отключает возможность использовать резервное значение описания, указанное в **Конфигурации сайта**, если оно доступно.

* **Суммаризация описания** → Использовать `Simple Content Summarization`, который берёт контент страницы для создания аннотации, или `PHP.Science Textrank Algorithm`, который использует сложный алгоритм, чтобы выделить то, что считает важными частями контента страницы, и составить из них аннотацию.

## Использование

Вкладка **SEO Magic** отображается для каждой страницы, которая одновременно **опубликована** и **видима**. Это значит, что родительская **модульная страница** покажет вкладку, а **модульные подстраницы** — нет.

Сразу после установки плагина следует выполнить индексацию или обход сайта, чтобы сгенерировать данные SEO, которые используются для автоматического создания описания и ключевых слов, а также для формирования оценки SEO для каждой страницы. Для правильной работы требуется установленный плагин **sitemap**. Это можно сделать несколькими способами:

1. Из **быстрой панели** админки. Просто нажмите на иконку волшебной палочки, чтобы запустить процесс.

2. Из параметров **Плагины** -> **SEO Magic**. Затем нажмите кнопку **Перегенерировать данные SEO**.

3. Из CLI можно запустить процесс индексации следующей командой:

    ```shell
    bin/plugin seo-magic process https://my-site.example/sitemap.json
    ```

    Где указанный URL — это URL вашей карты сайта, доступной при установленном плагине sitemap.

4. Также можно перегенерировать **данные SEO** для конкретной страницы, просто сохранив эту страницу, или выполнив следующую команду CLI:

    ```shell
    bin/plugin seo-magic process https://my-site.example/your/page-url
    ```

    Где указанный URL — это URL конкретной страницы на вашем сайте.

Каждый раз, когда вы сохраняете страницу, **данные SEO** обновляются. Они обновляются так же, как при индексации, но только для одной страницы. Так SEO Magic может проанализировать, как ваша реальная страница выглядит для поисковой системы. Это делает результаты более реалистичными, чем простая проверка данных.

### Проверка битых ссылок

Эта фича включена по умолчанию, и если вы её не отключите, при генерации **данных SEO** ссылки обходятся и проверяются на наличие битых. Кроме того, можно использовать новую команду CLI, чтобы быстро получить отчёт о состоянии битых ссылок в терминале:

```shell
bin/plugin seo-magic link-checker https://my-site.example/your/page-url
```

Где указанный URL — это URL вашей карты сайта, доступной при установленном плагине sitemap. Можно использовать необязательный параметр `-a`, чтобы показать все ссылки на странице, включая не битые. Например:

```shell
bin/plugin seo-magic link-checker https://my-site.example/your/page-url -a
```

Или можно указать URL конкретной страницы, чтобы проверить битые ссылки только на этой странице:

```shell
bin/plugin seo-magic link-checker https://my-site.example/your/page-url
```

Где указанный URL — это URL конкретной страницы на вашем сайте.

## Решение проблем

### Не удаётся перегенерировать данные SEO

Если при **перегенерации данных SEO** возникают проблемы с обходом сайта, сначала проверьте две вещи:

1. В новом браузере или в режиме инкогнито проверьте, доступен ли **URL карты сайта**, указанный в свойствах конфигурации Sitemap + SEO Magic. Если карта сайта не загружается, возможно, вы **отключили** плагин или изменили **URL карты сайта** — проверьте это в первую очередь.

2. Если у вас запрашивают имя пользователя и пароль, эту защиту нужно отключить, прежде чем карта сайта станет доступна для SEO Magic.

3. Если у вас разработческий SSL-сертификат и появляется запрос **принять сертификат**, это тоже может быть проблемой для SEO Magic. Он не сможет обойти ваши страницы для перегенерации данных SEO, если обычный браузер этого не может.

### Метаданные, заданные в контенте, не отображаются в браузере {: #metadata-set-in-content-is-not-showing-up-in-brows }

Наиболее вероятная причина в этом случае — используемая тема может не содержать стандартный фрагмент шаблона метаданных, который включает динамически заданные метаданные. Это распространённая ситуация, когда разработчик темы просто жёстко задал конкретные метатеги. Чтобы SEO Magic работал правильно, нужно использовать стандартный подход к метаданным.

Проверьте свою тему: скорее всего, файл `partials/base.html.twig` существует и содержит что-то вроде этого:

```twig
<meta charset="utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
{% include 'partials/metadata.html.twig' %}
```

Если в нём **нет** этого включения `partials/metadata.html.twig` (а оно на самом деле предоставляется самим ядром Grav), вам следует удалить любые другие пользовательские метатеги (3 показанных здесь можно оставить) и добавить включение, как показано.

### Тайм-ауты проверки ссылок

Если при проверке ссылок возникают тайм-ауты, увеличьте **тайм-аут проверки ссылок**. Значение по умолчанию — 10 секунд, и его может не хватать, когда страница не кэширована или размещена на медленном сервере.

Также стоит подумать об увеличении значения **Максимум повторов**, если для доступа к ссылке в пределах тайм-аута требуется несколько попаданий в кэш.

### Блокировка проверки ссылок

На некоторых сайтах действуют сложные правила файрвола, чтобы останавливать DDoS-атаки и другие обращения нечеловеческих скриптов. Проверка ссылок может их спровоцировать, поэтому вот подходы, которые можно попробовать, чтобы смягчить такие ситуации:

* **Внесите в белый список сайты, которые часто создают проблемы**. Некоторые сайты быстро блокируют шквал запросов **кодом ошибки 429** (слишком много запросов). Если у вас много ссылок на сайт, который выдаёт такую ошибку, внесите этот сайт в белый список.

* **Используйте localhost, если это возможно**. Если ваш сайт находится за прокси, файрволом или другим прокси-сервисом с ограничением частоты запросов (например, Cloudflare), любые запросы с вашего сервера на проверку собственных ссылок, вероятно, будут отправлены как от обычного клиента, то есть по полному URL, а значит, могут быть заблокированы. Способ обойти это для собственных ссылок — добавить простую запись в файл `/etc/hosts`, где ваш публичный URL указывает на IP-адрес localhost (например, `127.0.0.1`).
