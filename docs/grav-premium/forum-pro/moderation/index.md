# Модерация {: #moderation }

Forum Pro устроен так, чтобы **модераторам не требовался доступ к админке**. Почти всё происходит на самом форуме, поэтому модерацию можно передать участникам сообщества, не отдавая им ключи от установки Grav.

## Роли модераторов {: #moderator-roles }

Выдайте роль в **Admin → Forum → Moderators**. Роль может быть:

- **Глобальной**, охватывающей весь форум, или
- **Ограниченной** конкретными разделами и категориями.

Модераторы с ограниченными правами видят действия модерации только там, где действует их роль. Это подходящая схема для большого форума, где разные люди следят за разными подфорумами.

## Очередь проверки на форуме {: #the-review-queue-on-the-forum }

`{forum}/queue` — рабочая область модератора. В ней четыре вкладки, у каждой есть актуальный счётчик:

| Вкладка | Что содержит |
|---|---|
| **Спам** | Контент, который проверка спама оценила выше `spam.spam_threshold` |
| **Ожидает одобрения** | Контент, задержанный предмодерацией или оценённый выше `spam.pending_threshold` |
| **Пожалобы** | Сообщения, на которые пожаловались участники |
| **Удалённое** | Недавно удалённые сообщения и темы в пределах срока хранения |

В каждой карточке показаны автор, число его сообщений, возраст сообщения, **оценка спама** и сам контент. Действия выполняются одним нажатием:

- **Опубликовать** — выпускает сообщение
- **Удалить** — удаляет его с возможностью восстановления (см. ниже)
- **Удалить и заблокировать автора** — делает и то и другое сразу; быстрый путь для очевидного спамера
- **Показать в теме** — переходит к сообщению в контексте

**Пошаговый режим проверки** проводит по всей очереди на месте, поэтому разбор пятидесяти элементов не требует пятидесяти загрузок страницы.

Сотрудники также видят задержанные и spam-сообщения **прямо в ветках**, с кнопкой **Опубликовать** рядом, поэтому ложное срабатывание можно исправить без перехода в очередь.

## Массовая очередь в админке {: #the-bulk-queue-in-the-admin }

**Admin → Forum → Queue** охватывает те же задачи с представлениями ожидающих, спама и помеченных, а также добавляет **массовые действия до 100 элементов за раз** и блокировку в один клик. Используйте очередь админки для разбора накопившегося, а очередь форума — для повседневной работы.

## Предмодерация {: #premoderation }

Настраивается для каждой категории в **Structure → Edit**. Категория может задерживать сообщения:

- **Только новых участников**, где «новый» означает меньше `moderation.new_member_post_threshold` опубликованных сообщений, или
- **Всех**, что нужно для категории, где не должно быть ни одного непроверенного сообщения.

## Жалобы участников {: #member-reports }

Участники помечают сообщения, которые, по их мнению, нарушают правила. Когда сообщение набирает `moderation.auto_hide_flag_threshold` открытых жалоб (по умолчанию 3), оно **автоматически скрывается до проверки**, поэтому сообщество может подавить оскорбительный контент до того, как проснётся модератор.

```yaml
moderation:
  auto_hide_flag_threshold: 3   # 0 отключает автоматическое скрытие
```

Частота жалоб ограничивается для каждого участника параметром `spam.max_flags_per_hour`, что не позволяет использовать жалобы для травли.

Жалобы сохраняют **снимок контента**, поэтому исходный текст остаётся даже если автор потом его изменит. Снимки удаляются по расписанию `retention.purge_flag_snapshots_after_days`.

## Модерация внутри темы {: #in-topic-moderation }

Действия с темой находятся в меню с гаечным ключом рядом с заголовком темы:

- **Закрепить** / **Открепить**
- **Закрыть** / **Открыть**
- **Скрыть** / **Показать**
- **Переместить** в другую категорию
- **Удалить** / **Восстановить**

Действия с сообщением находятся в компактном ряду значков с меню «ещё»: **скрыть**, **пометить как спам**, **восстановить**, **удалить** и **скопировать ссылку**.

## Блокировки {: #bans }

Блокировка может быть:

- **Глобальной** или **ограниченной** разделами и категориями
- **Временной** (со сроком) или **бессрочной**
- С **причиной** и возможностью **апелляции** заблокированного участника

### Судьба контента {: #content-disposition }

При блокировке выбирается, что делать с написанным:

| Вариант | Эффект |
|---|---|
| **Оставить** | Контент остаётся видимым |
| **Скрыть всё** | Всё скрывается с возможностью отмены |
| **Анонимизировать** | Контент остаётся, авторство удаляется |
| **Удалить всё** | Всё мягко удаляется |

Большие объёмы передаются в очередь фоновых заданий, поэтому блокировка спамера с 4 000 сообщений завершается сразу, а не по тайм-ауту.

Заблокированные участники **распознаются при попытке зарегистрироваться снова** с теми же идентификаторами.

### Снятие блокировки {: #lifting-a-ban }

**Admin → Forum → Bans** перечисляет все активные блокировки с кнопкой **Снять** в один клик, которая также возвращает скрытый блокировкой контент. Сотрудники могут снять блокировку и из профиля участника на форуме. Переключите представление в админке, чтобы увидеть снятые и истёкшие блокировки и полную историю.

## Отмена действий {: #undo }

Удаление можно отменить в пределах срока хранения.

- Вкладка **Удалённое** в очереди форума перечисляет всё недавно удалённое — отдельные сообщения и целые темы, включая spam-ветки, удалённые через **Удалить и заблокировать**. Для каждой записи показано, кто, когда и почему её удалил, и есть кнопка **Восстановить**.
- Удалённые сообщения и темы также имеют встроенное действие **Восстановить** для сотрудников.

После `retention.purge_deleted_after_days` (по умолчанию 30) контент удаляется окончательно. Это окно восстановления, а не архив.

## Журнал аудита {: #the-audit-log }

Каждое действие сотрудников записывается: публикации, удаления, восстановления, блокировки, снятия блокировок, выдача ролей, изменения рангов и значков, доступ к пожалованным личным сообщениям. Журнал позволяет через три месяца ответить на вопрос «кто это удалил и почему».

## Юридические удержания {: #legal-holds }

**Юридическое удержание** освобождает участника, тему или сообщение от всей автоматической очистки. Сроки хранения не затрагивают удержанный контент, как и процесс очистки. Используйте его для всего, что расследуется или подлежит сохранению по запросу.

## Дайджест модераторов {: #the-moderator-digest }

```yaml
moderation:
  mod_digest: true
  mod_digest_time: '00:00'
  mod_digest_timezone: America/Denver
```

Ежедневное письмо каждому модератору с количеством элементов в очереди и активностью с момента прошлого дайджеста, отправляемое в заданное местное время в выбранном часовом поясе. В спокойные дни оно **не отправляется**, поэтому не превращается в шум, который модераторы учатся игнорировать.

## Обслуживание и режим только для чтения {: #maintenance-and-read-only-mode }

```yaml
maintenance:
  enabled: true
  include_staff: false
  message: "Back at 14:00 UTC after a database migration."
```

Участники могут просматривать форум, но не писать, не ставить реакции и не регистрироваться — на форуме или через [REST API](../rest-api/index.md); необязательный баннер объясняет причину. При `include_staff: false` сотрудники сохраняют полный доступ и могут работать во время режима обслуживания. Установите `true` для полной блокировки, например на время большого импорта.
