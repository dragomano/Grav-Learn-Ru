# Уведомления и электронная почта {: #notifications-and-email }

У системы уведомлений Forum Pro одна задача: сообщать участникам о том, что им важно, не заваливая их лишним.

## Колокольчик {: #the-bell }

Авторизованные участники видят **колокольчик уведомлений** на [панели инструментов участника](../members-and-accounts/index.md#the-member-toolbar) с актуальным числом непрочитанных. Он охватывает:

- Ответы в темах, которые участник отслеживает
- **Цитаты** его сообщений
- **@упоминания**
- Активность в отслеживаемых разделах
- **Решения модерации** по его контенту
- **Значки**, которые ему выдали
- Принятие его ответа **как решения**

`{forum}/notifications` перечисляет всё это с переходом к сообщению в один клик и действием **отметить всё прочитанным**.

## Всплывающие уведомления {: #live-toasts }

При включённых [обновлениях в реальном времени](../realtime/index.md) в момент появления ответа, упоминания или личного сообщения выезжает небольшая карточка. В ней указан отправитель, показан фрагмент личного сообщения и есть прямая ссылка на сообщение или беседу.

## Объединение серии уведомлений {: #burst-coalescing }

Двенадцать ответов в отслеживаемой теме дают **одну** запись в колокольчике, а не двенадцать. Именно от этого зависит, будут ли уведомления включены постоянно или их отключат на второй неделе.

## Уровни отслеживания {: #watch-levels }

Участники выбирают уровень отслеживания **для темы** и **для всего раздела** в списке, где объясняется каждый уровень:

| Уровень | Поведение |
|---|---|
| **Отслеживание** | Уведомления о каждом новом ответе |
| **Обычный** | Уведомления об ответах на сообщения, цитатах и упоминаниях |
| **Без звука** | Уведомлений нет, а тема или раздел скрываются в списках |

Участники **автоматически отслеживают** темы, которые создают или в которых отвечают. Это значение по умолчанию можно изменить в настройках, чтобы тот, кто отвечает на множество вопросов, не подписывался на каждую затронутую ветку.

## Электронная почта {: #email }

Почта повторяет колокольчик с учётом предпочтений участника и настраивается каждым участником в `{forum}/settings`:

| Настройка | Поведение |
|---|---|
| **Сразу** | Отправляется по мере событий, но не чаще одного письма по теме за окно |
| **Ежедневно** | Дайджест раз в день |
| **Еженедельно** | Дайджест раз в неделю |
| **Никогда** | Только колокольчик |

Переключатели по типам позволяют получать упоминания сразу, а всё остальное — в дайджесте.

```yaml
email:
  throttle_minutes: 15   # не более одного письма-уведомления участнику по теме за окно
```

Каждое письмо содержит **подписанную ссылку для отказа в один клик**, поэтому участник может остановить конкретный поток, не входя на сайт.

> [!NOTE] Примечание
> Для исходящей почты нужен плагин **Email** и рабочий транспорт. Без него колокольчик продолжает работать, но письма не доставляются.

## Доставка {: #delivery }

Почтовые уведомления **ставятся в очередь** и обрабатываются [фоновым процессом](../installation/index.md#the-background-worker) с повторными попытками и задержкой при сбое. Важны два свойства:

- Сообщения **адресованы индивидуально**. Forum Pro никогда не помещает участников в скрытую копию, поэтому один возврат письма не раскрывает весь список.
- Отправленные данные **удаляются по расписанию** (`retention.purge_sent_emails_after_days`, по умолчанию 7 дней), поэтому в базе не накапливается копия каждого когда-либо отправленного уведомления.

Состояние доставки можно проверить в **Admin → Forum → Status**, где показано количество ожидающих, неудачных и завершённых заданий.

## Личные сообщения {: #private-messages }

`{forum}/messages` — полноценная система обмена сообщениями между участниками.

```yaml
messages:
  enabled: true
  max_participants: 5           # человек в беседе, включая инициатора
  max_threads_per_hour: 10      # 0 отключает
  max_messages_per_minute: 10   # 0 отключает
```

- Беседы бывают **один на один или групповыми**, до `max_participants` человек.
- **Конверт** на панели инструментов показывает актуальное число непрочитанных, а новые ответы появляются в открытой беседе без обновления страницы.
- **Архивирование** разделяет входящие на активные и архивные.
- **Массовое архивирование и удаление** с выбором всех на странице и всех N элементов помогает очистить тысячи импортированных сообщений, сохранив несколько нужных. Выберите всё, снимите отметки с тех, что нужно оставить, и удалите остальное.
- **Блокировка** останавливает новые беседы и прямые ответы в обе стороны.
- На сообщения можно **пожаловаться модераторам**, которые видят только пожалованное сообщение, а доступ записывается в [журнал аудита](../moderation/index.md#the-audit-log).

Вложения в личных сообщениях используют ту же систему загрузки, что и сообщения на форуме, поэтому действуют те же ограничения размера и типов файлов.

> [!NOTE] Примечание
> URL вложений — это capability-URL без проверки авторизации: зная URL, построенный по содержимому, файл можно получить. Это осознанный компромисс, который делает возможными дедупликацию и доставку через CDN. Считайте вложение из личного сообщения потенциально доступным при утечке, а не секретным хранилищем.

## Временные участники и сообщения {: #provisional-members-and-messages }

При `provisional.block_messages: true` (значение по умолчанию) новые учётные записи не могут начинать личные беседы. Это закрывает самый распространённый способ спама на форуме с публичными профилями участников. См. [Защиту от спама](../spam-protection/index.md#provisional-members).
