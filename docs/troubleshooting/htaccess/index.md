# htaccess

Grav поставляется с собственным файлом `.htaccess`. Этот файл обеспечивает правильную работу Grav, и его нужно хранить в корневой папке. Вы можете столкнуться с проблемами, которые решаются с помощью файла `.htaccess`.

Apache — одно из самых популярных серверных решений, доступных сегодня. Он бесплатный и широко распространён почти повсюду. К сожалению, Apache не идеален, и иногда файл `.htaccess` может доставить головную боль. Не волнуйтесь: это почти всегда исправимо.

## Как редактировать .htaccess в Windows и macOS

Файл .htaccess — скрытый, то есть по умолчанию пользователи macOS и Windows не увидят его в файловом менеджере (Finder), пока не включат показ скрытых файлов.

В **macOS**:

1. Откройте **Terminal**.
2. Введите `defaults write com.apple.finder AppleShowAllFiles YES` в **Terminal** и нажмите **return**.
3. Введите `killall Finder` в **Terminal** и нажмите **return**.

Теперь вы должны увидеть файл `.htaccess` в корневой папке распакованной папки Grav. Вернуть настройки в исходное скрытое состояние можно, повторив процесс и введя `NO` в конце шага 2 вместо `YES`.

В **Windows 10**:

1. Откройте **Проводник**.
2. Выберите вкладку **View**.
3. Поставьте галочку рядом с **Hidden Items**.

Снятие этой галочки снова скроет эти файлы и вернёт **Проводник** в состояние по умолчанию.

## Проверка .htaccess

Допустим, вы открываете браузер, переходите на новый сайт Grav и… его там нет! На месте вашего прекрасного сайта Grav — большое жирное сообщение `Not Found`. Приятного в этом мало, но решение может быть таким простым, как настройка файла `.htaccess`.

Первый шаг в решении проблем с файлом `.htaccess` — убедиться, что сервер действительно подхватывает и использует этот файл. Проверьте, что файл лежит в корневой папке сайта Grav, где ему и положено быть, и что он правильно называется `.htaccess` с ведущей точкой (`.`).

Если файл на месте, следующий шаг — проверить, подхватывает ли его сервер. Это просто: достаточно добавить одну строку в начало файла.

Для проверки откройте `.htaccess` в текстовом редакторе. Затем создайте новую первую строку, впишите в неё текст `Test.` и сохраните.

`![Проверка HTACCESS](test.png?classes=border,shadow)`

Сама по себе эта ошибка проблему не решает, но она показывает, что сервер разбирает именно тот `.htaccess`, который лежит в корне сайта Grav.

Если такой ошибки нет, убедитесь, что файл лежит в корневой папке сайта. Это должен быть файл из исходной установки Grav. Именно поэтому мы рекомендуем распаковывать архив Grav и перемещать целиком эту папку туда, где должен быть сайт на сервере, а не копировать файлы и вставлять их. Так все файлы и структура папок сохраняются, и подобных проблем не возникает.

## Решение проблем со сломанным .htaccess

Если после редактирования .htaccess ничего не изменилось, возможно, нужно убедиться, что `.htaccess` включён. Иначе сервер даже не будет его искать.

Вот что можно сделать:

Найдите и откройте файл `httpd.conf` или `apache.conf` в текстовом редакторе. В Windows это, скорее всего, Блокнот или редактор для разработки. Текстовые процессоры могут добавить лишнюю информацию, которая только усугубит проблему.

Затем найдите в файле область `Directory`. Там должен быть такой блок текста:

```text linenums="1"
#
# AllowOverride управляет тем, какие директивы можно размещать в файлах .htaccess.
# Это может быть "All", "None" или любая комбинация ключевых слов:
#   Options FileInfo AuthConfig Limit
#
AllowOverride All
```

Если `AllowOverride` задан как `None` или что-то кроме `All`, нужно изменить его на `All` и сохранить. Для применения изменения потребуется перезапуск сервера Apache.

После этого ещё раз проверьте сайт.
