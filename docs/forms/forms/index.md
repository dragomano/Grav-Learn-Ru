# Формы на сайте

Плагин **Form** позволяет создавать практически любые формы на сайте. По сути, это конструктор форм, который можно использовать на собственных страницах. Прежде чем идти дальше, не забудьте установить [плагин **Form**](https://github.com/getgrav/grav-plugin-form) командой `bin/gpm install form`, если он ещё не установлен.

Чтобы понять, как работает плагин **Form**, начнём с создания простой формы.

> [!TIP] Совет
> В выпуске **Form 2.0** имя формы (**name of the form**) теперь обязательно передаётся скрытым полем. Если вы используете `forms.html.twig`, предоставляемый плагином Form, это обрабатывается автоматически. Однако если вы переопределили стандартный `forms.html.twig` в своей теме или плагине, добавьте `{% include "forms/fields/formname/formname.html.twig" %}` в свой файл Twig, который отрисовывает форму, вручную.

## Создание простой формы {: #create-a-simple-single-form }

Чтобы добавить форму на страницу сайта, создайте страницу и установите ей Page File «Form». Это можно сделать через админку или напрямую в файловой системе, назвав страницу `form.md`.

Например, `user/pages/03.your-form/form.md`.

Содержимое этой страницы будет таким:

```yaml linenums="1"
---
title: A Page with an Example Form
form:
    name: contact-form
    fields:
        name:
          label: Name
          placeholder: Enter your name
          autofocus: on
          autocomplete: on
          type: text
          validate:
            required: true

        email:
          label: Email
          placeholder: Enter your email address
          type: email
          validate:
            required: true

    buttons:
        submit:
          type: submit
          value: Submit
        reset:
          type: reset
          value: Reset

    process:
        email:
          from: "{{ config.plugins.email.from }}"
          to:
            - "{{ config.plugins.email.to }}"
            - "{{ form.value.email }}"
          subject: "[Feedback] {{ form.value.name|e }}"
          body: "{% include 'forms/data.html.twig' %}"
        save:
          fileprefix: feedback-
          dateformat: Ymd-His-u
          extension: txt
          body: "{% include 'forms/data.save.txt.twig' %}"
        message: Thank you for your feedback!
        display: thankyou

---

# My Form

Regular **markdown** content goes here...
```

> [!NOTE] Примечание
> Это содержимое файла `form.md` в том виде, в каком он лежит на диске. Чтобы сделать то же самое из админки, откройте страницу и используйте редактор **Page File** на вкладке Advanced — он редактирует frontmatter и содержимое вместе.

Этого достаточно, чтобы показать форму на странице под её содержимым. Это простая форма с полями имени и email и двумя кнопками: одна отправляет форму, другая сбрасывает поля. Подробнее о доступных полях, которые предоставляет плагин Form, [читайте в следующем разделе](fields-available/index.md).

Что происходит при нажатии кнопки `Submit`? По очереди выполняются действия из `process`. О других действиях можно узнать в разделе [доступных параметров](reference-form-actions/index.md) или [создать собственное](reference-form-actions/index.md#custom-actions).

1. На указанный email отправляется письмо с темой `[Feedback] [введённое имя]`. Тело письма определяется в файле `forms/data.html.twig` используемой темы.

2. В `user/data` создаётся файл с данными формы. Шаблон определяется в `forms/data.save.txt.twig`, который предоставляет плагин Form и который может переопределить используемая тема. Отправленные значения записываются как обычный текст, поэтому значение вроде `Tom & Jerry` сохраняется ровно так, как было введено.

3. Показывается подстраница `thankyou` вместе с переданным сообщением. Страница `thankyou` должна быть подстраницей страницы с формой.

> [!NOTE] Примечание
> Убедитесь, что плагин **Email** настроен правильно, чтобы письма успешно отправлялись.

## Несколько форм

С выпуском **Form Plugin v2.0** в одной странице можно определять несколько форм. Синтаксис похож, но каждая форма различается по имени — в данном случае `contact-form` и `newsletter-form`:

```yaml linenums="1"
forms:
    contact-form:
        fields:
            ...
        buttons:
            ...
        process:
            ...

    newsletter-form:
        fields:
            ...
        buttons:
            ...
        process:
            ...
```

Этот формат можно использовать и для одной формы, указав только одну форму под `forms:`:

```yaml linenums="1"
forms:
    contact-form:
        fields:
            ...
        buttons:
            ...
        process:
            ...
```

## Вывод форм из Twig

Самый простой способ вставить форму — включить файл Twig в шаблон, который отрисовывает страницу с определённой формой. Например:

```twig linenums="1"
{% include "forms/form.html.twig" %}
```

Будет использован шаблон Twig, предоставляемый самим плагином Form. Он отрисует форму так, как вы её определили на странице, и покажет сообщение об успехе или ошибки при отправке формы.

Однако есть более мощный способ вывода форм, использующий поддержку нескольких форм. В этом случае вы передаёте шаблону Twig параметр `form:`, указывая форму, которую хотите вывести:

```twig linenums="1"
{% include "forms/form.html.twig" with { form: forms('contact-form') } %}
```

Этот способ позволяет выбрать конкретную форму по имени. Можно даже указать имя формы, определённой на других страницах. Если все имена форм на сайте уникальны, Grav найдёт и отрисует нужную форму!

Можно даже вывести несколько форм на одной странице:

```twig linenums="1"
# Contact Form
{% include "forms/form.html.twig" with { form: forms('contact-form') } %}

# Newsletter Signup
{% include "forms/form.html.twig" with { form: forms('newsletter-form') } %}
```

Другой способ вывести форму — сослаться не на имя формы, а на маршрут страницы, используя массив:

```twig linenums="1"
# Contact Form
{% include "forms/form.html.twig" with { form: forms( {route:'/forms/contact'} ) } %}
```

Так будет найдена первая форма на странице с маршрутом `/forms/contact`.

## Вывод форм в содержимом страницы

Форму также можно вывести прямо в содержимом страницы (например, `default.md`), даже если на этой странице форма не определена. Просто передайте имя или маршрут формы.

> [!CAUTION] Внимание
> **Обработка Twig** должна быть включена, а **кэш страниц** — отключён, чтобы форма обрабатывалась на странице динамически, а не отдавалась из статического кэша, и обработка формы могла выполняться.

```twig linenums="1"
---
title: Page with Forms
process:
  twig: true
cache_enable: false
---

# Contact Form
{% include "forms/form.html.twig" with {form: forms('contact-form')} %}

# Newsletter Signup
{% include "forms/form.html.twig" with {form: forms( {route: '/newsletter-signup'} ) } %}
```

## Nonce форм и кэширование

Каждая форма, которую выводит плагин, содержит скрытое поле `form-nonce`. Это токен безопасности (CSRF-nonce), который Grav проверяет при отправке. Если nonce отсутствует или больше не действителен, отправка отклоняется с ответом **`403 Forbidden`** и не обрабатывается.

Nonce основан на времени и действует примерно 12 часов. Обычно это незаметно, но в двух распространённых ситуациях отправка может завершиться ошибкой `403`:

* страница с формой была **отдана из кэша** (кэш страниц Grav или CDN/прокси перед сайтом) с nonce, срок действия которого уже истёк;
* посетитель **оставил страницу открытой** дольше срока жизни nonce перед отправкой.

В обоих случаях симптом одинаковый: форма только что работала, но отправка с устаревшей страницы возвращает `403`.

Чтобы избежать этого на кэшируемых или долго открытых страницах, включите параметр **`refresh_nonce`** в конфигурации плагина Form (`user/config/plugins/form.yaml`):

```yaml linenums="1"
enabled: true
refresh_nonce: true
```

Когда `refresh_nonce` включён, плагин загружает небольшой JavaScript-помощник, который периодически запрашивает в фоне свежий nonce (до истечения текущего) и обновляет поле формы. Так формы на агрессивно кэшируемых или долго открытых страницах остаются отправляемыми без перезагрузки посетителем.

> [!NOTE] Примечание
> Интервал обновления вычисляется из `system.session.timeout` (с ограничением до ~12-часового срока жизни nonce), поэтому отдельного интервала для настройки нет.

## Модульные формы

В предыдущих версиях плагина Form, чтобы форма отображалась в модульной подстранице общей **модульной** страницы, форму нужно было определять в **модульной странице верхнего уровня**. Тогда она обрабатывалась и была доступна для вывода в модульной подстранице.

В **Form v2.0** форму можно определить прямо в модульной подстранице, как любую другую. Однако если форма там не найдена, плагин ищет её на «текущей странице», то есть на модульной странице верхнего уровня, поэтому полная обратная совместимость с подходом 1.0 сохраняется.

Шаблон Twig модульной подстраницы также можно настроить так, чтобы он использовал форму с другой страницы, как в примерах выше.

> [!WARNING] Предупреждение
> При использовании формы, определённой в модульной подстранице, задайте **action:** родительской модульной страницы и настройте форму с действием **redirect:** или **display:**, поскольку модульная подстраница не подходит для загрузки при отправке формы: она **не маршрутизируется** и поэтому недоступна браузеру.

Вот пример, который находится в `form/modular/_form/form.md`:

```yaml linenums="1"
---
title: Modular Form

form:
  action: '/form/modular'
  inline_errors: true
  fields:
    person.name:
      type: text
      label: Name
      validate:
        required: true

  buttons:
    submit:
      type: submit
      value: Submit

  process:
    message: "Thank you from your submission <b>{{ form.value('person.name') }}</b>!"
    reset: true
    display: '/form/modular'  
---

## Modular Form
```
