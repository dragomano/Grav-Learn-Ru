# Как использовать формы на модульных страницах

## Использование форм на модульных страницах

Если ваша тема не предоставляет файл `templates/forms/form.html.twig`, она не настроена для использования форм, но не бойтесь — просто скопируйте шаблоны форм из Antimatter, темы Grav по умолчанию:

- `templates/form.html.twig`
- `templates/formdata.html.twig`

Теперь создайте модульную папку с типом страницы `form.md`.

Например: `01.your-modular-page/_contact/form.md`.

Страница `form.md` не будет содержать определения формы. Она лишь указывает, что именно эта часть должна выводить форму.

Важно: установите

```yaml linenums="1"
---
cache_enable: false
---
```

во frontmatter этой страницы, потому что из-за того, как работают модульные страницы, при пропуске этого форма будет закэширована вместе с nonce, который генерируется каждые 12 часов. Когда 12 часов истекут, форма перестанет работать до обновления кэша. Для отдельных страниц с формами этот шаг не нужен.

Теперь добавьте заголовок формы в основную модульную страницу `modular.md`.

Страница modular.md должна содержать всё определение формы с полями и т. д., как если бы это был заголовок «полностраничного» файла form.md. С собственным путём страницы в поле `form.action`.

> [!NOTE] Примечание
> В Form v2.0 форму можно определить прямо в модульной подстранице, как любую другую. Однако если она там не найдена, плагин ищет её на «текущей странице», то есть на модульной странице верхнего уровня, поэтому полная обратная совместимость с подходом 1.0 сохраняется. !!!

Например:

```yaml linenums="1"
---
content:
    items: '@self.modules'

form:
    action: /your-modular-page
    name: my-nice-form
    fields:
        -
            name: name
            label: Name
            placeholder: 'Enter your name'
            autofocus: 'on'
            autocomplete: 'on'
            type: text
            default: test

    buttons:
        -
            type: submit
            value: Submit

    process:
        -
            message: 'Thank you for your feedback!'
---
```

В заголовке формы обязательно добавьте параметр `action` с маршрутом модульной страницы.

Как в примере выше.
Этот шаг нужен, потому что если явно не добавить `form.action`, код обычно ищет маршрут страницы, но поскольку форма находится в модульной подстранице, а не на реальной странице, путь получается неверным и отправка формы ломается.

Так, если модульная страница — например, `site.com/my-page`, просто укажите `form: action: /my-page` в `modular.md`.
Даже если модульная страница — главная, используйте маршрут страницы, например `form: action: /home`.

#### Решение проблем с формами на модульных страницах

Лучший способ отладить форму — сначала вернуться к основам и добавлять свои изменения по одному, чтобы увидеть, что может идти не так.

- Советую создать «обычную форму», убедиться, что она работает, а затем попробовать поместить её в модульную форму.
- Попробуйте заставить форму работать в скелете на основе Antimatter — он предоставляет все нужные файлы.
- Если поля формы не появляются и у вас установлен плагин Assets, отключите или удалите его. Есть известная проблема, из-за которой он ломает модульные формы; она скоро будет исправлена.
