# Модульные страницы

Концепцию **модульных страниц** поначалу немного сложно понять, но когда вы её освоите, то увидите, насколько удобно их использовать. **Модульная страница** — это коллекция страниц, сложенных друг на друга, чтобы создать единую страницу.

---

Это позволяет создавать сложную структуру страницы по принципу **строительных кирпичиков LEGO**, а кто не любит LEGO?!

## Что такое модульные страницы и чем они не являются?

В Grav [страницы](../content-pages/index.md) — широкое понятие, охватывающее почти любые комбинации элементов, которые только можно вообразить на сайте. Важно, что модульные страницы — подмножество этого понятия, но не то же самое, что обычная страница. Обычная страница довольно самостоятельна в том смысле, что Grav отрендерит и отобразит её, не завися от другого контента, например других страниц или дочерних страниц. У модульной страницы, однако, нет дочерних страниц. Это можно проиллюстрировать, представив простую структуру страниц:

Обычная страница по адресу _domain.com/books_ содержит сведения о книгах в продаже. У этой страницы есть несколько дочерних страниц, например _domain.com/books/gullivers-travels_ и _domain.com/books/the-hobbit_. Их папки названы так же, как адрес, который рендерит Grav: `/pages/books`, `/pages/books/gullivers-travels` и `/pages/books/the-hobbit`. Такая структура не сработает в модульной странице.

У модульной страницы нет дочерних страниц в том же смысле; вместо этого у неё есть **модули**, составляющие части страницы. Так, вместо разных книг, расположенных под страницей верхнего уровня, модульная страница отображает свои модули **на той же странице**. «Путешествия Гулливера» и «Хоббит» появляются на _domain.com/books_ с путями `/pages/books/_gullivers-travels` и `/pages/books/_the-hobbit`. Таким образом, модульные страницы напрямую не совместимы с обычными страницами и имеют собственную структуру.

## Пример структуры папок

На примере нашего **One-Page Skeleton** подробнее объясним, как работают модульные страницы.

Сама **модульная страница** собирается из страниц, находящихся в подпапках основной папки страницы. В случае нашего One-Page Skeleton эта страница расположена в папке `01.home`. Внутри неё находится единственный файл `modular.md`, который сообщает Grav, какие подстраницы включить для сборки модульной страницы и в каком порядке их отображать. Имя этого файла важно, потому что оно указывает Grav использовать шаблон `modular.html.twig` из текущей темы для рендеринга страницы.

Эти подстраницы находятся в папках, имена которых начинаются с символа подчёркивания (`_`). Используя подчёркивание, вы сообщаете Grav, что это **модули**, а не самостоятельные страницы. Например, папки подстраниц могут называться `_features` или `_showcase`. Эти страницы **немаршрутизируемые** — на них нельзя перейти напрямую в браузере, — и **невидимые** — они не отображаются в меню.

В случае нашего One-Page Skeleton мы создали структуру папок, изображённую ниже.

`![Listing Page](modular-explainer-2.jpg?classes=shadow)`

Каждая подпапка содержит Markdown-файл, который действует как страница.

Затем данные из этих папок модулей — включая Markdown-файлы, изображения и т. д. — извлекаются и отображаются на модульной странице. Это достигается созданием основной страницы, определением [коллекции страниц](../collections/index.md) в YAML-метаданных основной страницы и последующим перебором этой коллекции в Twig-шаблоне для генерации объединённой HTML-страницы. В теме уже должен быть шаблон `modular.html.twig`, который это делает и используется при создании страницы модульного типа. Вот простой пример из `modular.html.twig`:

```twig linenums="1"
{% for module in page.collection() %}
    {{ module.content|raw }}
{% endfor %}
```

## Настройка основной страницы

Как видите, каждый раздел извлекает контент из отдельной папки модуля. Какие папки модулей используются и в каком порядке, определяется в основном Markdown-файле в родительской папке модуля. Вот содержимое файла `modular.md` в папке `01.home`.

```yaml linenums="1"
---
title: One Page Demo Site
menu: Home
onpage_menu: true
body_classes: "modular header-image fullwidth"

content:
    items: '@self.modules'
    order:
        by: default
        dir: asc
        custom:
            - _showcase
            - _highlights
            - _callout
            - _features
---
```

Как видите, фактического контента в этом файле нет. Всё определяется в YAML-метаданных страницы в заголовке. Здесь задаются **заголовок** страницы, назначение в **меню** и другие настройки, которые можно найти на обычной странице. Поле [Content](../headers/index.md) указывает Grav создать контент на основе коллекции модульных страниц и даже задаёт собственный ручной порядок их рендеринга.

## Модули

`![Listing Page](modular-explainer-3.jpg?classes=shadow)`

Markdown-файл каждого модуля может иметь собственный шаблон, настройки и т. д. Практически у него есть большинство фич и настроек обычной страницы, просто он не рендерится как таковая. Мы рекомендуем размещать настройки для всей страницы, например **таксономию**, в основном Markdown-файле, который управляет всей страницей.

Сами модульные страницы обрабатываются так же, как обычные. Вот пример с файлом `text.md` на странице `_callout`, которая появляется в середине модульной страницы.

```markdown linenums="1"
---
title: Homepage Callout
image_align: right
---

## Content Unchained

No longer are you a _slave to your CMS_. Grav **empowers** you to create anything from a [simple one-page site](#), a [beautiful blog](#), a powerful and feature-rich [product site](#), or pretty much anything you can dream up!
```

Как видите, заголовок страницы содержит базовую информацию, которую можно найти на обычной странице. У него есть собственный заголовок, на который можно ссылаться, и здесь можно задать [пользовательские параметры страницы](../headers/index.md#custom-page-headers), например выравнивание изображения, как и на любой другой странице.

Файл шаблона для `text.md` должен находиться в папке `/templates/modular` вашей темы и называться `text.html.twig`. Этот файл, как и любой Twig-шаблон для другой страницы, определяет настройки, а также любые стилистические отличия от базовой страницы.

```twig linenums="1"
<div class="modular-row callout">
    {% set image = page.media.images|first %}
    {% if image %}
        {{ image.cropResize(400,400).html('','','align-'~page.header.image_align)|raw }}
    {% endif %}
{{ content|raw }}
</div>
```

В целом модульные страницы очень просты. Нужно просто привыкнуть к идее, что каждый раздел страницы определяется в модуле, у которого есть собственная папка внутри фактической страницы. Они отображаются посетителям все сразу, но организованы немного иначе, чем обычные страницы. Не стесняйтесь экспериментировать и открывать, чего можно добиться с помощью модульной страницы в Grav.
