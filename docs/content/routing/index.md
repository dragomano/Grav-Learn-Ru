# Маршрутизация

Как мы уже описывали во вводном [разделе «Страницы → Папки»](../content-pages/index.md#folders), **маршрутизация** в Grav в первую очередь управляется структурой папок, которую вы используете при создании контента сайта.

---

Бывают сценарии, когда нужна большая гибкость, и Grav поставляется с множеством инструментов и параметров конфигурации, чтобы упростить вам жизнь в этом отношении.

Представьте, что вы перенесли сайт с другой CMS-платформы на Grav. У вас есть несколько вариантов настройки нового сайта:

1. Попытаться воспроизвести URL старого сайта, построив соответствующую структуру папок.
2. Построить новый сайт так, как хотите вы, а затем заставить веб-сервер «переписать» старые URL, перенаправляя клиентов на новые места.
3. Построить новый сайт так, как хотите вы, и настроить Grav для перенаправления клиентов со старых URL на новые места.

Есть много других случаев, когда сайт Grav должен отвечать на URL, отличные от тех, что диктует структура папок, и Grav располагает следующими возможностями, помогающими достичь ваших целей.

## Переопределение маршрута и перенаправления на уровне страницы

Как описано в разделе [Заголовки → Маршруты](../headers/index.md#routes), для страницы можно явно задать параметры маршрутизации для **маршрута по умолчанию**, а также массив **псевдонимов маршрутов**:

```yaml linenums="1"
routes:
  default: '/my/example/page'
  canonical: '/canonical/url/alias'
  aliases:
    - '/some/other/route'
    - '/can-be-any-valid-slug'
```

Они обрабатываются и кэшируются для каждой страницы и доступны вместе с тем, что мы называем **исходным маршрутом** (raw route) — маршрутом на основе **слагов** иерархии страниц (именно так Grav по умолчанию вычисляет маршрут). Поэтому даже если вы задаёте собственные маршруты страницы, **исходный маршрут** всё равно остаётся действительным.

Подобно маршрутизации на уровне страницы, Grav также поддерживает перенаправления на уровне страницы, указывая целевую страницу в заголовке страницы. Подробнее см. в разделе [Заголовки → Перенаправление](../headers/index.md#redirect).

```yaml linenums="1"
redirect: '/some/custom/route[303]'
```

## Маршруты и перенаправления на уровне сайта

У Grav есть мощный механизм на основе регулярных выражений для обработки **псевдонимов маршрутов** и **перенаправлений** с одной страницы на другую. Эта фича особенно полезна при переносе сайта на Grav, когда нужно, чтобы старые URL продолжали работать на новом сайте. Чаще всего это лучше всего делать через **правила перезаписи** веб-сервера, но иногда удобнее и гибче позволить Grav обработать их самому.

Они настраиваются через [конфигурацию сайта](../../basics/grav-configuration/index.md#site-configuration). Grav поставляется с образцом `system/config/site.yaml`, но вы можете переопределить или добавить любые собственные настройки, отредактировав файл `user/config/site.yaml`.

> [!CAUTION] Внимание
> Все правила перенаправления применяются к пути из слагов, начинающемуся после языковой части (если используются многоязычные страницы).

> [!TIP] Совет
> В маршрутах, которые нужно сопоставить, необходимо экранировать определённые символы. Это особенно важно знать при переносе старого сайта, где ссылки содержали устаревшие расширения файлов (например, `.php`) или параметры URL (`?foo=bar`). В этих примерах точку и вопросительный знак **нужно экранировать**, например `/index\.php\?foo=bar: '/new/location'`.

### Псевдонимы маршрутов

#### Простые псевдонимы

Самый простой вид псевдонима — прямое взаимно однозначное сопоставление. В разделе `routes:` файла `site.yaml` можно создать список сопоставлений, указывающих псевдоним и фактический маршрут, который следует использовать.

> [!CAUTION] Внимание
> Важно отметить, что эти псевдонимы используются, только если по указанному маршруту не найдена действительная страница.

```yaml linenums="1"
routes:
  /something/else: '/blog/focus-and-blur'
```

Если запросить URL `http://my-site.example/something/else` и это не действительная страница, определение маршрутов фактически отдаст вам страницу по адресу `/blog/focus-and-blur`, если она существует. Это не **перенаправляет** пользователя на указанную страницу, а просто отображает страницу при запросе псевдонима.

> [!CAUTION] Внимание
> Здесь важен отступ: без него перенаправление маршрута не сработает.

#### Псевдонимы на основе регулярных выражений

Более продвинутый тип псевдонимов позволяет использовать простое **регулярное выражение**, чтобы сопоставить часть псевдонима с маршрутом. Например, если у вас есть:

```yaml linenums="1"
routes:
   /another/(.*): '/blog/$1'
```

это направит группу-шаблон из псевдонима в маршрут, поэтому `http://my-site.example/another/focus-and-blur` фактически отобразит страницу по маршруту `/blog/focus-and-blur`. Это мощный способ сопоставить один набор URL другому. Отлично подходит для переноса сайта с WordPress на Grav :)

Можно также выполнять сопоставление, чтобы захватить любой псевдоним и направить его на конкретный маршрут:

```yaml linenums="1"
routes:
  /one-ring/(.*): '/blog/sunshine-in-the-hills'
```

С таким псевдонимом любой URL, соответствующий шаблону, — `/one-ring/to-rule-them-all` или `/one-ring/is-mine.html` — покажет контент страницы с маршрутом `/blog/sunshine-in-the-hills`.

Можно проявить гораздо больше изобретательности и сопоставлять несколько элементов или использовать любой синтаксис регулярных выражений:

```yaml linenums="1"
routes:
  /complex/(category|section)/(.*): /blog/$1/folder/$2
```

Это сопоставит и перепишет следующее:

```text linenums="1"
/complex/category/article-1      -> /blog/category/folder/article-1
/complex/section/article-2.html  -> /blog/section/folder/article-2.html
```

Этот маршрут не сопоставится ни с чем, что не начинается с `complex/category` или `complex/section`. Дополнительную информацию и тестирование регулярных выражений можно найти на отличном ресурсе [Regexr.com](http://regexr.com/).

### Перенаправления

Другая связанная с **псевдонимами маршрутов** возможность — **перенаправления**. Они похожи, но вместо сохранения URL и простой отдачи контента по псевдониму маршрута Grav фактически перенаправляет браузер на сопоставленную страницу.

На перенаправления влияют три параметра конфигурации системного уровня:

```yaml linenums="1"
pages:
  redirect_default_route: false
  redirect_default_code: 302
  redirect_trailing_slash: true
```

* `redirect_default_route` позволяет Grav автоматически перенаправлять на маршрут страницы по умолчанию.
* `redirect_default_code` позволяет задать коды перенаправления HTTP по умолчанию:
    * **301**: Постоянное перенаправление. Клиенты, делающие последующие запросы к этому ресурсу, должны использовать новый URI. Клиенты не должны автоматически следовать перенаправлению для запросов POST/PUT/DELETE.
    * **302**: Перенаправление по неопределённой причине. Клиенты, делающие последующие запросы к этому ресурсу, не должны использовать новый URI. Клиенты не должны автоматически следовать перенаправлению для запросов POST/PUT/DELETE.
    * **303**: Перенаправление по неопределённой причине. Обычно означает «Операция завершена, продолжайте в другом месте». Клиенты, делающие последующие запросы к этому ресурсу, не должны использовать новый URI. Клиенты должны следовать перенаправлению для запросов POST/PUT/DELETE.
    * **307**: Временное перенаправление. Ресурс может вернуться в это место позже. Клиенты, делающие последующие запросы к этому ресурсу, должны использовать старый URI. Клиенты не должны автоматически следовать перенаправлению для запросов POST/PUT/DELETE.
* параметр `redirect_trailing_slash` позволяет перенаправлять на версию текущего URL без завершающей косой черты.

Например:

```yaml linenums="1"
redirects:
    /jungle: '/blog/the-urban-jungle'
```

Можно также явно передать код перенаправления в квадратных скобках `[]` как часть URL:

```yaml linenums="1"
redirects:
    /jungle: '/blog/the-urban-jungle[303]'
```

Если открыть в браузере `http://my-site.example/jungle`, вас фактически перенаправит на страницу `http://my-site.example/blog/the-urban-jungle`.

Те же возможности регулярных выражений, что и для псевдонимов маршрутов, есть и для перенаправлений. Например:

```yaml linenums="1"
redirects:
    /redirect-test/(.*): /$1
    /complex/(category|section)/(.*): /blog/$1/folder/$2
```

Они выглядят почти так же, как версия с псевдонимами маршрутов, но вместо прозрачного отображения новой страницы Grav фактически перенаправляет браузер и загружает новую страницу явно.

## Скрытие домашнего маршрута

Когда вы назначаете определённую страницу домашней страницей сайта через файл `system.yaml`:

```yaml linenums="1"
home:
  alias: '/home'
```

вы фактически указываете Grav добавить маршрут `/` как псевдоним этой страницы. Это значит, что когда Grav запрашивает страницу для URL `/`, он находит назначенную вами страницу.

Однако Grav не делает ничего особенного для страниц, находящихся под этой домашней страницей. Так, если у вас есть страница `/blog`, отображающая список записей блога, и вы назначите её домашней, она будет работать как ожидается. Но если вы щёлкнете по записи блога, находящейся в папке `/blog`, URL может быть `/blog/my-blog-post`. Это ожидаемое поведение, но, возможно, не то, что вам нужно. В `system.yaml` есть новый параметр, позволяющий скрыть этот верхний уровень `/blog` из маршрута, если его включить.

Включить это поведение можно, переключив следующее значение:

```yaml linenums="1"
home:
  hide_in_urls: true
```
